**2. 논문체 문장**
- 33행 "…둘 + …하나를 한 프로젝트에 담았습니다" — 구조 예고
- 44행 "즉 소재는 …이고, 만드는 방식 자체도 실험이었습니다" — 되짚는 요약
- 202행 "설계 결정 (정직한 '왜')" — 자의식적 제목
- bullet마다 3줄씩 붙어 스캔이 안 됨

**3. 처음 보는 사람이 막히는 용어**
모험의 서 · 로아ON(게임 콘텐츠, 설명 없음) / 하네스(42행) · 레이트리밋(83행, 아래선 "호출 제한") ·
토큰버킷(다이어그램) / 제목은 "아이템", 본문은 "품목"으로 불일치.

**4. 가장 보여줄 것이 서랍에 있음**

클릭해야 열리고 모바일에선 더 안 열린다 — 사실상 없는 것과 같다.

## 결정 (착수 전 확정)

- **엔지니어링 상세**: 핵심만 본문 승격 + 나머지 접기. 승격 대상 = 아키텍처 다이어그램,
  설계 결정 3개, 대표 API 1개. 접기 유지 = 로컬 실행, 전체 API 표, 프로젝트 구조 트리.
- **게임/전문 용어**: 괄호로 짧게 1회 풀고 넘어간다. 별도 용어집을 만들지 않는다.
- **본문 분량**: `<details>` 밖 약 130행 목표.

## Task 1 — 본문 재구성 (중복 제거 + 구조 개편)

- **files:** `README.md`
- **action:**
  - 상단 경고 박스(47–51행) 삭제 → 인과 부인은 "설계에서 고민한 것" 항목 **1회만** 남긴다.
  - AI 협업을 41–42행에서 빼고 하단 섹션(107–116행) 하나로 통합, 3줄로 압축.
  - 57행의 중복 링크 제거(16행 히어로 링크 유지). "직접 보기" 표는 화면 목록만 남긴다.
  - `<details>`에서 **아키텍처 다이어그램 · 설계 결정 3개 · 대표 API 1개**를 본문으로 이동.
    설계 결정은 5개 중 3개만 남긴다 — 호출 제한 / 인과 부인 / 점진적 구축(뼈대 먼저).
    Redis 선택·아이콘 폴백은 접기로 내린다(덜 차별적).
  - 최종 목차: 무엇을 하나 → 왜 만들었나 → 기술 스택 → 어떻게 동작하나 → 설계에서 고민한 것
    → 배포 → AI를 어떻게 썼나 → `<details>` 개발자용 → 개발자
- **verify:** `<details>` 밖 행 수가 약 130행. 이벤트 인과 부인·AI 협업·라이브 링크가 각각 1회만
  등장하는지 `grep`으로 확인. mermaid 블록이 본문에 있고 문법이 깨지지 않았는지 GitHub 프리뷰 확인.
- **done:** 접지 않아도 아키텍처와 설계 판단이 보이고, 같은 내용이 두 번 나오지 않는다.
