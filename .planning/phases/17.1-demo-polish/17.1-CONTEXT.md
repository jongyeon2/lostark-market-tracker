## Phase Boundary

라이브 배포(Phase 18) 전 데모 품질을 다듬는다. 다섯 갈래: (1) 대시보드 수집 헬스 카드를 클라이언트 화면에서 제거하고 관리자 콘솔에서만 'API 상태'로 노출(POLISH-01), (2) 각인 큐레이션을 현행 유효각인으로 갱신 — 딜러 11 + 서포터 7(POLISH-02), (3) 재료 큐레이션을 티어4로 갱신 — 운명의 파괴석/수호석 결정 추가·융화재료는 아비도스만·오레하 제거(POLISH-03), (4) 대시보드를 바둑판 그리드에서 카테고리별 세로 섹션(각인 → 재료)으로 재구성(POLISH-04), (5) event-impact 상관≠인과 주의 문구를 이해하기 쉽게 개선(POLISH-05).

**이 페이즈의 실제 델타(스카우트 확인):** 수집/캐시/event-impact 백엔드 로직 **0줄**(Core Value 가드). 변경은 (a) 큐레이션 데이터 층 — `WatchlistSeeder`(수집 정체성) + `SyntheticDemoData`(seed 합성 시세)를 15→22개로 재잠금(신규 10개 API 재검증 = Phase 12 spike-then-lock 동형), (b) 프론트 read-path — 대시보드 레이아웃/HealthCard 배치, `roleGroup.ts` 라벨, `CorrelationBanner` 카피에 한정.

**In scope:** 큐레이션 22개 재잠금(각인 18 + 재료 4) · 신규 10개 실 API `Id`/`Icon`/`CategoryCode` 스파이크 · 대시보드 HealthCard 제거 + 관리자 'API 상태' 리네임 · 대시보드 세로 섹션 재구성(가로 행 카드) · MATERIAL 라벨 '융화재료'→'재료' · CorrelationBanner 문구 개선.
**Out of scope (Phase 18):** 공개 배포 · Dockerfile · prod 프로파일 · 보안 게이트 · 서빙 방식. **(v2):** 새 roleGroup(HONING) 도입 · 그룹 필터 토글 · 등급 색상/정렬.

## Implementation Decisions

### 큐레이션 갱신 & 스파이크 (POLISH-02/03)
- **D-01:** 큐레이션을 **15→22개로 교체**한다. 세트 델타:
  - **딜러 각인 9→11:** 유지 8(원한·예리한 둔기·저주받은 인형·아드레날린·타격의 대가·기습의 대가·돌격대장·결투의 대가) · **신규 3(질량 증가·슈퍼 차지·바리케이드)** · **제거 1(정밀 단도, `65204305`)**
  - **서포터 각인 2→7:** 유지 2(각성·전문의) · **신규 5(구슬동자·마나의 흐름·폭발물 전문가·분쇄의 주먹·중갑착용)**
  - **재료 4→4:** 유지 2(아비도스 융화 재료 `6861012`·상급 아비도스 융화 재료 `6861013`) · **제거 2(상급 오레하 `6861009`·최상급 오레하 `6861011`)** · **신규 2(운명의 파괴석 결정·운명의 수호석 결정 — 재련 재료)**
- **D-02:** 신규 10개(각인 8 + 재료 2)의 **실 API `Id`/`Icon`/`CategoryCode`를 실 키로 라이브 실측**한다(Phase 12 spike-then-lock 동형, 1회). 런타임 키 불필요·데이터만 잠금. 실 `.env` 키 유효가 전제([[lostark-dev-collection-key-debug]] — AUTH_ERROR 시 collection_run·`.env` 키 확인).
- **D-03:** 각인은 **전부 '유물' 등급으로 통일**한다(displayName `유물 X 각인서`, `category=40000`). 기존 11종이 유물이므로 신규 8종도 유물 각인서로 큐레이션 — 스파이크가 각 유물 각인서의 실 거래 `Id`/시세 존재를 확인. 유물 각인서는 `use_9_25.png` 글리프 공유(Phase 14 D-06) → 신규도 **라벨로 식별**(fallback 미대체).
- **D-04:** 운명의 파괴석/수호석 결정(재련 재료 — 융화재료 아님, `CategoryCode`≠50010)은 **기존 `MATERIAL` roleGroup 버킷에 넣고, 라벨을 '융화재료'→'재료'로 일반화**한다. `roleGroup.ts`의 `ROLE_LABEL.MATERIAL` 단일 변경 — zod 스키마·역할 3색·`sortByRole` 정렬 **무변경**(최소 변경, 백엔드 roleGroup enum 무변경). 새 roleGroup(HONING) 도입은 v2로 유예.
- **D-05:** **seed(`SyntheticDemoData`)도 watchlist와 동일 22개로 동기화**한다. watchlist(수집 정체성) + seed(합성 시세)를 함께 갱신 → API 키 없이 로컬/테스트에서 새 큐레이션 재현(Phase 17 D-09 이중 트랙·리뷰어 진입장벽 0 유지).
- **D-06:** **불변 가드** — 수집(`PriceCollector`)/캐시/event-impact 로직 **0줄**. 큐레이션 변경은 `WatchlistSeeder`+`SyntheticDemoData` 데이터 목록 + read-path 라벨에 한정.

### 헬스 카드 이관 & 대시보드 정직성 (POLISH-01)
- **D-07:** 대시보드(`DashboardPage`)에서 **`<HealthCard/>`를 완전 제거**한다(현재 L30 full-width). HealthCard는 관리자 콘솔 `CollectionSection`에 **이미 재사용 중**(Phase 15 D-11, ADMINUI-05)이므로 관리자 노출은 그대로 유지 — 클라이언트 화면에서만 뺀다.
- **D-08:** 라벨을 **'API 상태' 단일 제목으로 통일**한다 — `HealthCard`의 `CardTitle` '수집 헬스'→'API 상태', 관리자 `CollectionSection`의 바깥 래퍼 제목 '수집 상태' 제거(섹션>카드 중첩 해소) → 관리자에서도 'API 상태' 카드 하나로.
- **D-09:** REALDATA-03 '수집 중/데이터 없음' 정직성은 **기존 자산으로 충분** — 대시보드는 per-card 가격 pending(`ItemCard`) + 아이템 그리드 `AsyncBoundary` 빈/로딩 카피(Phase 17 D-03/04)가 담당. HealthCard 제거로 별도 대체 표시는 만들지 않는다(집계 ops 상태는 관리자 관심사).

### 대시보드 재구성 (POLISH-04)
- **D-10:** 반응형 그리드(`grid sm:2 lg:3열`)를 **카테고리별 세로 섹션 2개**로 재구성 — 상위 **각인**(DEALER+SUPPORT) → 상위 **재료**(MATERIAL). roleGroup 버킷 재사용, 섹션 간 각인→재료 순.
- **D-11:** 각인 섹션 내부는 **딜러 → 서포터 순**(기존 `sortByRole` 순서와 정합), 각 카드의 기존 `RoleBadge`(딜러/서포터)로 구분 — 무거운 딜러/서포터 서브헤더 없이 깔끔하게. 섹션 내 이름(ko-KR) 정렬.
- **D-12:** 카드 형태를 **정사각 그리드 → 가로 전폭 행**(위→아래 순차)으로 바꾼다. **보존(회귀 금지):** 카드 딥링크(`<Link to="/timeline?item={id}">`, Phase 16 CARD-02) · `ItemIcon` · `RoleBadge` · 골드 가격(`minPrice`) · 수집 시각(`formatKst`). 고유번호는 Phase 16에서 이미 제거됨.

### 주의 문구 개선 (POLISH-05)
- **D-13:** `CorrelationBanner` 문구를 번역투 없이 개선한다 — **제목 "해석에 주의하세요"**, **본문 "이벤트와 가격 변동이 비슷한 시점에 나타났다는 의미일 뿐, 이벤트가 가격을 움직였다는 근거는 아닙니다."** 신뢰성 가드 보존: 중립 Info 아이콘(경고 삼각형 아님)·상시 노출·닫기 버튼 없음(과대해석 방지)·`default`(slate) variant 유지.

### Claude's Discretion
- 가로 행 카드의 정확한 내부 레이아웃(아이콘/이름/배지 좌측 · 가격/시각 우측 정렬, 구분선·간격·8pt 스페이싱), hover/focus 피드백(accent blue-600은 focus-visible 링에만, Phase 16 D-05와 일관).
- 각인 섹션 내 딜러/서포터 소제목을 넣을지(기본: 미포함, RoleBadge로 구분). 넣는다면 경량 텍스트.
- 신규 각인의 **유물 등급 미존재/시세 희소 시 fallback**(스파이크 실측 판단 — 예: 해당 각인만 등급 조정 or 목록 제외 후 사용자 확인).
- 운명의 파괴석/수호석 결정의 `itemGroup` 필드값(예 '강화재료' 일반 유지 vs '재련재료') — 카드 표기에 쓰이지 않으므로(Phase 16 D-01) 스파이크/planner 재량.
- 섹션 제목 타이포/스페이싱(07-UI-SPEC 카피·상태 컴포넌트 패턴과 일관되게).
- 문구 개선 시 제목/본문 미세 어휘(D-13 취지 유지 하에).

## Specific Ideas

- **현행 메타 반영이 포트폴리오 서사:** 큐레이션을 T3 오레하→T4(아비도스+운명 결정) 및 현행 유효각인(딜러 11·서포터 7)으로 갱신 = "실시간 로아 메타의 고변동 바스켓". 도메인 지식 차별점(검색으로 못 얻는)을 데이터에 반영.
- **정보 배치의 관점 분리:** 수집 헬스(파이프라인 살아있음)는 운영자 관심사 → 관리자 'API 상태'로, 클라이언트 대시보드는 "무엇을·지금 얼마"에 집중. 헬스 카드는 이미 관리자에 있으므로 대시보드에서만 제거하면 됨.
- **세로 섹션(각인→재료):** 카테고리로 시선을 정리하고 가로 넓은 행으로 품목명·가격을 한 줄에 — 바둑판보다 스캔하기 쉬운 배치.

</specifics>
