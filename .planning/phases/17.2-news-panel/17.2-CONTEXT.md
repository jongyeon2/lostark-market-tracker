<domain>
## Phase Boundary

대시보드 물품 카드(`max-w-3xl`)를 좁히며 생긴 우측 여백에 로스트아크 진행중 이벤트·공지사항을 표 형식으로 노출한다. 로아 공식 `/news/events`·`/news/notices` API를 저빈도 폴러 + Redis 캐시로 서빙하며, 프로젝트의 수집→캐시→서빙 파이프라인 패턴을 재사용한다.

**In scope:** 이벤트·공지 소싱(공식 API)·Redis 캐시·`GET /api/news`·대시보드 우측 사이드바 패널·정직성 상태·Core Value 가드.
**Out of scope:** 쿠폰코드(공식 API 부재 → 이후 관리자 수동 입력), 썸네일 이미지(1차 텍스트 표), 뉴스 PostgreSQL 적재(휘발성 표시 데이터 — Redis로 충분), 경매장/보석 소스.
</domain>

<decisions>
## Implementation Decisions

- **D-01 소싱/서빙(Approach A):** 로아 공식 `/news/events` + `/news/notices` → 저빈도 `@Scheduled` 폴러(기본 6h + 부팅 1회) → Redis 캐시(키 `news:latest`, TTL 12h) → `GET /api/news` read 엔드포인트. 온디맨드(B)·프론트 직접(C, 가드 위반) 기각.
- **D-02 백엔드 신규 패키지 `com.lostark.tracker.news`:** `LostarkNewsClient`(RestClient, 기존 base-url/key 재사용) · `NewsService`(캐시 관리 getLatest/refresh) · `NewsPoller`(@Scheduled) · `NewsController`(`GET /api/news`). **Redis 캐시-only, PostgreSQL 미적재.**
- **D-03 프론트:** `useNews()`(React Query, staleTime ~5분) · `NewsPanel.tsx`(이벤트 표 + 공지 표, `AsyncBoundary`) · `DashboardPage` lg 2-column. 컨텐츠 `max-w-6xl`, `lg:grid lg:grid-cols-[minmax(0,1fr)_20rem] lg:gap-8`(좌 물품 / 우 NewsPanel ≈320px), 기존 단독 `max-w-3xl` 제거(그리드가 폭 제어). 모바일(< lg): 물품 아래 세로 스택.
- **D-04 표시/상호작용:** 이벤트 표(제목·기간 StartDate~EndDate·링크) 종료임박순 ~6개; 공지 표(타입 뱃지·제목·날짜) 최신순 ~6개. 행 클릭 → 로아 공식 `Link` 새 탭(`target="_blank" rel="noopener noreferrer"`). 로딩/빈/에러 = 기존 `AsyncBoundary`.
- **D-05 필드 검증 스파이크(spike-then-lock):** 구현 전 `/news/events`·`/news/notices` 실 응답 필드명을 라이브 1회 실측(기존 `MarketsApiSpikeTest` 하니스 확장, `@Disabled`·spike 프로파일·키 안전 계승, 공개 메타만). DTO 매핑(EventDTO/NoticeDTO) 잠금. 저위험이라 경량.
- **D-06 Core Value 가드:** `PriceCollector`·`CollectionConfig`·가격 캐시·`EventImpactService`·`WatchlistSeeder`·`SyntheticDemoData` **0줄**. 뉴스는 독립 패키지·독립 스케줄·독립 Redis 키(6h당 2요청 → 마켓 예산 무영향). 프론트는 `GET /api/news`만 소비(로아 직접 호출 금지), 키 서버 env only.
- **D-07 정직성:** 폴 실패 시 마지막 캐시 유지 + `updatedAt` 미갱신(경고 로그). read 엔드포인트는 마지막 스냅샷 서빙. 캐시 비면 빈 배열 + `updatedAt=null` → 프론트 빈/로딩.

### Claude's Discretion
- 이벤트/공지 표의 정확한 컬럼·행 스타일·타입 뱃지 색(기존 Card/타이포/8pt 재사용, RoleBadge류 패턴 참고).
- 신선도('업데이트 지연') 표기 구현 여부(우선순위 낮음, `updatedAt` 기반).
- 폴 주기·표시 개수의 config화(기본 6h/~6개).
- NewsPanel을 단일 Card 2섹션 vs 2 Card로 구성.
- zod `newsResponseSchema` 세부(boundary loud-fail 패턴 유지).
</decisions>

## Specific Ideas
- loawa.com처럼 이벤트·공지를 한눈에 — 물품 옆 여백을 정보 밀도로 채워 데모 완성도 향상.

</specifics>
