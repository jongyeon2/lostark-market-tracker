<objective>
Put the **shared-secret authentication gate** in front of the admin surface built in 04-01 (ADMIN-03, Phase Success Criterion 1): every `/api/admin/**` request must present the correct `X-Admin-Secret` header or get **401** — and the 401 body is the **same** `{timestamp,status,error,message}` contract as the rest of the API (D-02). Verification is a **hand-rolled header-based `OncePerRequestFilter`** doing a constant-time compare against an env-sourced secret, registered in a `SecurityFilterChain` (D-01) — single shared secret, one layer, no HTTP Basic and no user/role model (that is v2).

The critical regression risk: adding `spring-boot-starter-security` locks **all** endpoints by default. So the filter chain must explicitly `permitAll` the Phase 1-3 public read surface (`GET /api/items/**`, `/api/health/**`, `/actuator/**`) — that is the difference between "secured admin" and "broke the whole read API" (D-01). The secret is an env placeholder (`${ADMIN_API_SECRET:}`); blank => fail **closed** (admin 401) while the collection pipeline and public reads keep running, because the Core Value pipeline must never depend on the admin secret.

Purpose: a public repo with unauthenticated write endpoints is a hiring red flag (PROJECT 6A); this is the one-layer gate that closes it. Returning **401, not 403**, on the same JSON contract is the deliberate "the security layer speaks the same API contract" signal for the interview (D-02). Because 04-01's admin ITs already send the header, this wave drops the gate in with **zero test retrofit** and adds one focused auth IT.

Output: `build.gradle` (+security starter); `SecurityConfig` (filter chain, permitAll surface, stateless, CSRF off); `AdminSecretFilter` (constant-time header check); `AdminAuthenticationEntryPoint` (401 JSON); the `admin.api.secret` env placeholder + test value + `.env.example` entry; and `AdminAuthGateIT`.
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |
