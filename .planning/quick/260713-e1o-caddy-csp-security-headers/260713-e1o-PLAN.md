# Quick Task 260713-e1o: Caddy CSP + 보안 헤더 보강

## 배경

Phase 18 라이브 배포 후 보안 검수(18-05 게이트)에서 6/6 항목은 라이브 통과했으나,
게이트 **밖** 하드닝 2건이 남았다. 그중 하나가 **CSP 헤더 부재**(🟡 낮음).
`frontend/Caddyfile`의 `header` 블록에 HSTS·nosniff·X-Frame-Options·Referrer-Policy는
있으나 `Content-Security-Policy`가 없어 XSS 심층 방어가 비어 있다.

핵심 리스크: 잘못 잡은 CSP는 SPA(React/Vite + Recharts + Radix)를 깨뜨린다.
따라서 **추정이 아니라 라이브 실자산에 대해 실측 검증한** 정책만 넣는다.

## 라이브 실측 근거 (Playwright, page.route로 후보 CSP 주입 후 리로드)

| 리소스 | 실측 오리진 | 결론(디렉티브) |
|--------|------------|----------------|
| 진입 script | `/assets/index-*.js` (module, self), 인라인 script 0 | `script-src 'self'` |
| stylesheet | `/assets/index-*.css` (self) | `style-src 'self'` |
| 런타임 inline style | Recharts 차트/범례 스와치 18개 요소 `style="background-color:…"` | `style-src` 에 `'unsafe-inline'` **필수** |
| 폰트 | `/assets/inter-*.woff2` (@fontsource 번들, self) | `font-src 'self'` |
| 이미지 | `cdn-lostark.game.onstove.com` (아이콘 atlas + 배너) + self favicon | `img-src 'self' data: https://cdn-lostark.game.onstove.com` |
| API/데이터 | 전부 same-origin `/api/*` | `connect-src 'self'` |

**eval 판정:** 후보 CSP(`script-src 'self'`, unsafe-eval 없음) 주입 시 유일한 위반은
`script-src <- eval` 1건. 출처는 `index-*.js`의 `get value` 게터 내 `new Function()`(빈 body)
= 라이브러리 일회성 로드타임 기능 프로브(try/catch fallback). eval을 막은 상태에서
timeline·dashboard·impact 3페이지 전부 정상 렌더 + 콘솔 에러 0, Radix Select 드롭다운도
정상 작동(22개 옵션·floating-ui 위치계산 OK). → **기능 의존 아님. `'unsafe-eval'` 추가 안 함.**
(대가: 프로덕션 콘솔에 blocked-eval 경고 1줄이 남으나 무해. 하드닝 우선.)

## Task 1 — Caddyfile header 블록에 CSP + 하드닝 헤더 추가

**File:** `frontend/Caddyfile`

**Action:** 기존 `header { … }` 블록에 3개 헤더 추가:
- `Content-Security-Policy` — 위 실측 매핑 그대로
- `Permissions-Policy` — 미사용 브라우저 기능(geolocation/camera/mic/payment 등) 차단
- `Cross-Origin-Opener-Policy "same-origin"` — 브라우징 컨텍스트 격리(안전, 팝업/OAuth 없음)

의도적으로 **제외**: `Cross-Origin-Embedder-Policy require-corp`(onstove CDN 이미지가
CORP 헤더 없어 깨짐), `upgrade-insecure-requests`(불필요 — 모든 하위리소스 이미 https).

**Verify:**
1. `caddy validate`(컨테이너 빌드 시 실행) 또는 `docker compose config`로 문법 확인
2. 재배포 후 `curl -sI https://…` 에 `content-security-policy` 헤더 존재
3. 재배포 후 Playwright로 timeline/dashboard/impact 콘솔 `securitypolicyviolation` = eval 1건 외 0

**Done:** Caddyfile `header` 블록에 3개 헤더가 실측 검증된 값으로 들어가고,
문법 검증 통과. 라이브 반영은 사용자 VM 재배포(`docker compose -f docker-compose.prod.yml
--env-file .env.prod up -d --build caddy`)에서 발생.
