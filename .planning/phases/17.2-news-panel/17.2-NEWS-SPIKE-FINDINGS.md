## (b) `/news/events` 실측 필드 → **EventDTO** 매핑

실측 필드 키: `[Title, Thumbnail, Link, StartDate, EndDate, RewardDate]` (첫 항목, 전 항목 동일 구조)

| 실 필드(JSON) | 타입 | 샘플/포맷(공개) | → EventDTO 필드 | 비고 |
|---|---|---|---|---|
| `Title` | string | (한글 이벤트명) | `title` | 필수 |
| `Thumbnail` | string(URL) | `https://cdn-lostark.game.onstove.com/uploadfiles/banner/2026/….jpg` | `thumbnail` | 배너 이미지 URL(1차 표시 미사용, D-04). 값 존재 |
| `Link` | string(URL) | `https://lostark.game.onstove.com/Promotion/…` | `link` | 행 클릭 새 탭 대상 |
| `StartDate` | string(datetime) | `2026-06-24T06:00:00` (ISO-8601 **local, 오프셋 없음**) | `startDate` | 기간 시작 |
| `EndDate` | string(datetime) | `2026-07-22T06:00:00` | `endDate` | 기간 종료 → **종료임박순 정렬 키**(D-04) |
| `RewardDate` | string(datetime) \| null | `2026-07-29T06:00:00` | `rewardDate` | 보상 지급일. 일부 이벤트는 null 가능 → nullable로 매핑 |

**EventDTO 잠금:** `title`(String), `link`(String), `thumbnail`(String), `startDate`(String, ISO-8601), `endDate`(String, ISO-8601), `rewardDate`(String, nullable).
날짜는 오프셋이 없으므로 **문자열 그대로 통과**(백엔드에서 `LocalDateTime` 파싱 불필요 — 프론트가 표시 포맷팅). 매핑은 `@JsonProperty("Title")` 등 PascalCase→camelCase.

## (c) `/news/notices` 실측 필드 → **NoticeDTO** 매핑

실측 필드 키: `[Title, Date, Link, Type]` (전 항목 동일 구조)

| 실 필드(JSON) | 타입 | 샘플/포맷(공개) | → NoticeDTO 필드 | 비고 |
|---|---|---|---|---|
| `Title` | string | (한글 공지명) | `title` | 필수 |
| `Date` | string(datetime) | `2026-07-01T15:10:18.527` (ISO-8601 **local + 밀리초**) | `date` | **최신순 정렬 키**(D-04). events와 달리 밀리초 포함 |
| `Link` | string(URL) | `https://lostark.game.onstove.com/News/Notice/Views/13480` | `link` | 행 클릭 새 탭 대상 |
| `Type` | string | (한글 분류; 첫 페이지 **≥4개 distinct** 관측) | `type` | 타입 뱃지(D-04). **불투명 한글 문자열 통과** — 프론트가 문자열로 뱃지 색 매핑 |

**NoticeDTO 잠금:** `title`(String), `link`(String), `date`(String, ISO-8601+밀리초), `type`(String).
`Type`의 정확한 한글 enum 값은 콘솔 인코딩(CP949→XML) 단계에서 유실되어 이 세션에서 문자열 복구 불가 — 다만 **string 타입·≥4 distinct**는 측정 확정. 백엔드는 `type`을 **String 그대로 통과**(enum 잠그지 않음)하므로 DTO 매핑에 영향 없음. 프론트 뱃지는 값별 매핑 + 미지값 기본 스타일(loud-fail 아닌 graceful).

## (d) 17.2-02 백엔드 전사 지침 (spike-then-lock 전사)

- `NewsDtos.java`: `record NewsEvent(String title, String link, String thumbnail, String startDate, String endDate, String rewardDate)`, `record NewsNotice(String title, String date, String link, String type)` — PascalCase 실 필드는 `@JsonProperty`로 매핑.
- `LostarkNewsClient`: `GET /news/events` → `List<NewsEvent>`, `GET /news/notices` → `List<NewsNotice>`(배열 직접 역직렬화, 래퍼 없음). base-url/key는 기존 패턴 재사용(spike 클라이언트와 동일 헤더).
- 정렬(서비스/프론트): events = `endDate` 오름차순(종료임박), notices = `date` 내림차순(최신). 날짜는 문자열 비교로도 ISO-8601이라 안전하나, 정렬은 프론트 표시 로직에서 수행 가능(D-04).
- **추정 0건**: 필드명·타입·컨테이너 모두 위 실측값. 유일한 미확정은 `Type` enum 값(String 통과라 무영향).
