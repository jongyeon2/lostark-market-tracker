## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin (browser) → `/admin` gate | The React gate decides authenticated vs anonymous; the REAL security boundary is the backend `AdminSecretFilter` — the frontend gate is UX/exposure control, not the authority |
| sessionStorage ↔ JS | The secret lives in `sessionStorage`, readable by any script in the origin (XSS surface) |
| adminRequest → backend `/api/admin/**` | Every admin call carries `X-Admin-Secret`; a 401 means the secret is stale/rotated |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1502-01 | Information Disclosure (secret in storage / XSS window) | adminSecret.ts / sessionStorage | mitigate/accept | Use `sessionStorage` not `localStorage` (D-01) so the exposure window is one tab session; the secret is written ONLY by `setAdminSecret` and never rendered/logged. Residual XSS risk is accepted for a single-user demo and documented as the AUTH-V2 boundary (honesty narrative). No third-party script is added to `/admin`. |
| T-1502-02 | Information Disclosure (secret leaks into DOM/logs/errors) | login form / api.ts | mitigate | The secret is held only in component state + `sessionStorage`; the input is `type="password"`; `ApiError` carries status+path only; no `console.*`/error string interpolates the value. An acceptance check greps for the absence of a rendered secret. |
| T-1502-03 | Spoofing (client gate bypass to reach write UI) | AdminRoute gate | mitigate | The gate does not merely disable — it does not MOUNT the console subtree while anonymous (D-05), so no write control exists in the DOM. Even if bypassed client-side, every write still hits the backend `AdminSecretFilter` (401 without a valid secret) — the frontend gate is defense-in-depth, not the sole control. |
| T-1502-04 | Denial/confusion (stale secret keeps a dead session) | 401 interceptor | mitigate | A global 401 handler (D-03) clears the secret and returns to login with a clear message, so a rotated/expired secret cannot leave the admin stuck in a broken authenticated shell. |
| T-1502-05 | Tampering (accidental backend/public-surface change) | main.tsx / TopNav | mitigate | `/admin` is added as a sibling route with NO public nav link and NO change to public pages or backend; an acceptance check confirms changes are confined to `frontend/` and the public routes are untouched. |
