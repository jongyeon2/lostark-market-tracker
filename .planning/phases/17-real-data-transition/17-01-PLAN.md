<objective>
데이터가 아직 축적되지 않은 초기 상태에서도 3화면(Dashboard·Timeline·Impact)이 **빈 화면 없이 '수집 중/데이터 없음'을 정직히** 표시하게 만든다(REALDATA-03). 이는 단순 빈 화면 회피가 아니라 `collection_run`으로 "수집 파이프라인이 살아있는가"를 보여주는 **Core Value 가시화의 프론트 확장**이다. 순수 프론트엔드 변경으로 백엔드 `src/`는 0줄(D-08).

- **D-05 — 공유 기본 copy 교체:** `EmptyState.tsx`의 seed 하드코딩 기본 문구(`DEFAULT_BODY = 'seed 프로파일 백엔드를 기동하면 시세가 채워집니다 (SPRING_PROFILES_ACTIVE=seed).'`)를 **실데이터 기준 중립 문구**로 바꾼다. 공유 기본값이 더 이상 seed 기동을 전제하지 않는다.
- **D-03 — collection_run 기반 판정(단일 출처):** '수집 중'(run 존재/SUCCESS인데 데이터가 아직 희소·직전 시작) vs '데이터 없음'(NO_RUNS 또는 실패)을 구분하는 파생 로직을 `frontend/src/lib/collectionEmptyState.ts` **한 곳**에 둔다. 판정 근거는 기존 `GET /api/health/collection`(`CollectionHealth.status`)을 **무변경 소비** — `HealthCard`/`StatusBadge`가 이미 소비하는 계약.
- **D-04 — 화면별 맞춤 문구:** Dashboard(최신가 수집 중, per-card `ItemCard`) · Timeline(이 품목 시계열 수집 중, `ChartArea`) · Impact(이벤트 전후 비교엔 더 많은 데이터·이벤트 필요, `ImpactResults`). Impact는 **기존 sparse/stale 가드 위에 얹으며 재구현하지 않는다**.

Purpose: 조기 배포 후 축적 전제(REALDATA-03)에서 첫 수집 전/직후에도 화면이 "고장난 빈 화면"이 아니라 "파이프라인은 살아있고 데이터가 쌓이는 중"임을 정직히 보여준다.

Output: seed 하드코딩이 사라진 `EmptyState.tsx`, 새 파생 헬퍼 `collectionEmptyState.ts`, collection-aware 빈 상태를 표시하는 `ItemCard.tsx`·`TimelinePage.tsx`·`ImpactPage.tsx`. `cd frontend && npm run build` 그린, 백엔드 `src/` 0줄, 새 npm 의존성 0.
