## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `/api/health/collection` response → rendered health card | counts/status/lastRunAt/summaryMessage from the health endpoint are rendered into the card |
| Backend availability → card state | backend up/down/NO_RUNS drives the card's success/error/waiting branch |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-0802-01 | Information Disclosure (health internals leak) | HealthCard / SummaryMarker | mitigate | The card renders only the zod-validated categorical fields (counts, status, lastRunAt, categorical marker via SummaryMarker); it never renders raw exception text, and the response carries no secret field by design (DASH-02). The ErrorState (07-03) shows the fixed UI-SPEC copy, not a stack/response body (T-0703-03 carried forward). |
| T-0802-02 | Denial of Service / UX crash (health failure blanks screen) | HealthCard AsyncBoundary | mitigate | HealthCard owns its own `<AsyncBoundary>` (D-07/D-08): a backend-down or schema-mismatch error renders the in-card ErrorState with '다시 불러오기' (refetch), and NO_RUNS renders a waiting card — neither crashes nor blanks the item grid that 08-03 renders below (완료조건 #5). |
| T-0802-03 | Spoofing (NO_RUNS / FAILED misread as healthy) | HealthCard / StatusBadge | mitigate | NO_RUNS is rendered as an explicit '수집 대기' badge + waiting copy (not a silent empty), and FAILED renders the distinct '전체 실패'(down) badge — color + Korean label + icon together (08-01 a11y), so a not-yet-run or failed pipeline cannot visually pass as 정상. |
| T-0802-04 | Tampering / XSS (rendering API strings) | HealthCard | mitigate | All fields are rendered as JSX text children (React-escaped); no `dangerouslySetInnerHTML`. Values are zod-validated upstream (07-02 collectionHealthSchema) before reaching the render. |

</threat_model>
