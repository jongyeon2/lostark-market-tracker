<objective>
Make the tick **resilient and observable**: wrap each item fetch in an **explicit bounded retry** (max 3 attempts, exponential backoff, honoring 429 `Retry-After`) for transient failures (429, 5xx/timeout); treat **401/403 as fatal auth** (no retry, stop new calls, converge in-flight to failure, mark the run `AUTH_ERROR`); treat other 4xx as **skip-light** (no retry, no snapshot, counted failed); finalize the `collection_run` with the partial-failure status vocabulary (`SUCCESS`/`PARTIAL_SUCCESS`/`FAILED`) and **categorical `summary_message` markers** added via a new Flyway **V2** migration. Markers never carry the API key (D-08).

Purpose: This is the resilience + run-marker layer on top of the 02-02 collector. It delivers the **retry/skip half of COLL-04** (Retry-After + backoff + max-3 then skip; 401/5xx distinguished) and COLL-05 (failed item writes no snapshot, only run results), satisfying Success Criteria 3 (429 retried max-3 then skip without crash) and 4 (one failure doesn't block others). It also lands the deferred `summary_message` column (D-14) so `/health` (Phase 3, OPS-01) can later surface auth-error state — Phase 2 only produces the data, never exposes the key.

Output: a `V2__...sql` migration + `CollectionRun.summaryMessage`; a hand-rolled `RetryPolicy`; retry/error-class wiring in `ItemFetchService` + status/marker finalization in `PriceCollector`; a resilience IT + a retry unit test.
</objective>

## Phase Goal

**As a** reliable data pipeline, **I want** transient API errors retried within a bounded budget, fatal auth errors stopped and marked, and per-item failures isolated with a recorded run status, **so that** a flaky or rate-limited API (or an expired key) never crashes a tick, never blocks healthy items, and leaves an auditable run history with safe categorical markers.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Lostark API error responses -> retry/classification | Untrusted status codes/headers (incl. 429 Retry-After, 401) drive retry + run-marking decisions |
| collection_run.summary_message -> Phase 3 /health | Markers persisted here are later surfaced by OPS-01 health (read by operators) — must be secret-free |
| retry loop -> rate-limited API | Retries add outbound load against a 100/min budget |
