<objective>
Deliver the **latest-price read path** with a **hand-rolled Redis cache-aside** (explicit get/put/evict on a value-serializing RedisTemplate) and **evict-on-write invalidation** wired into the Phase 2 collection persist path. On a cache hit the second read does **zero** DB queries (the office-hours showcase); writing a new snapshot evicts the item's latest key so the next read reflects the new price. Also finish API-01 by filtering `GET /api/items` to active items, and lay the **404 half of the error contract** (custom `@RestControllerAdvice` + `ItemNotFoundException`) that 03-02/03-03 reuse.

Purpose: This is the Redis learning artifact of Phase 3 (PROJECT.md "Redis 캐시-어사이드", D-01/D-02/D-03). Cache-aside is hand-built (no `@Cacheable`) so both the read-fill and the write-invalidate are visible and explainable, paralleling the Phase 2 self-built token bucket. Evict-on-write is the bug-prone seam (stale cache failure mode from the design review) — it is proven directly here, not assumed.

Output: `CacheConfig` (value RedisTemplate) + `LatestPriceCache` (get/put/evict + safety TTL) + `LatestPriceResponse` DTO; `LatestPriceService`; `/latest` + active `/api/items` on `ItemController`; `ApiExceptionHandler` + `ItemNotFoundException` + `ApiErrorResponse` (404 contract); a read-only repo finder; an evict hook in `PriceCollector`; and a Testcontainers IT proving cache-hit-0-DB-reads, evict-on-write, and 404s.
</objective>
