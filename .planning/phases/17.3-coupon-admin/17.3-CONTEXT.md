<decisions>
## Implementation Decisions

### 만료일 처리
- **D-01:** 만료일은 **날짜만(`LocalDate`)** — 관리자 폼은 `type="date"` 입력(이벤트의 datetime-local과 다름). 쿠폰은 `expiresAt >= 오늘(서버 KST 날짜)`이면 유효로 판정해 그날 끝(23:59 KST)까지 노출한다. 시각 단위 만료 없음 — 입력·판정 단순.

### 대시보드 표시
- **D-02:** 뉴스 패널 내 쿠폰 섹션은 **맨 위**에 배치 — 순서는 쿠폰 → 진행중 이벤트 → 공지사항. 쿠폰이 가장 actionable(즉시 사용)이라 상단 노출.
- **D-03:** 코드 복사 성공 피드백 = **버튼 라벨/아이콘 일시 변경**(~2초 '복사됨!'/체크 후 원복). `navigator.clipboard.writeText` 사용, 신규 의존성 0(토스트 시스템 미도입).

### 데이터 정책
- **D-04:** 쿠폰 코드 **중복 허용** — `code` unique 제약 없음. 관리자가 같은 코드를 자유롭게 재등록 가능(단순·유연). 워치리스트의 externalItemId-unique 선례는 따르지 않는다.

### Claude's Discretion
- `reward`는 자유 텍스트(varchar) — 구조화 없음.
- 만료 판정 쿼리 구현(`expiresAt >= current_date` 등), 공개 목록 만료임박순 정렬 + ≤6 캡 위치(서비스/쿼리).
- admin 폼은 `EventSection` 레이아웃(Table + 인라인 폼 + mutation) 재사용, 날짜 입력은 `type="date"`.
- 쿠폰 행 표시 레이아웃(코드·보상·만료일 배치), 만료일 표기 형식(예: YYYY.MM.DD), 복사 버튼 위치·아이콘.
- 빈/로딩/에러 카피, zod boundary(couponSchema) loud-fail 세부.
- Flyway 마이그레이션 버전(다음 순번 V5)·컬럼 타입·엔티티/repository 세부.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- **이벤트 CRUD 전 스택이 쿠폰과 거의 1:1 미러링**: `GameEvent`→`Coupon`, `occurredAt`→`expiresAt`(단, LocalDate), `description`→`reward`. `AdminEventController`→`AdminCouponController`, `gameEventResponseSchema`→`couponSchema`, `useAdminEvents/useCreateEvent/useReplaceEvent/useDeleteEvent`→쿠폰 mutation, `EventSection`→`CouponSection`.
- `adminRequest`(X-Admin-Secret 자동첨부, 401→auto-logout) / `request`(공개 fetch+zod) — 그대로 재사용.
- `AsyncBoundary`, `Card` 프리미티브, `NewsPanel`의 섹션 구조(SectionHeading + 리스트) — 대시보드 쿠폰 섹션에 재사용.

### Established Patterns
- admin write = X-Admin-Secret 게이트(SecurityConfig `/api/admin/**` authenticated), 공개 read = `anyRequest().permitAll()` → `/api/coupons`·`/api/admin/coupons` 모두 SecurityConfig 무변경으로 동작.
- Flyway가 스키마 소유(JPA `ddl-auto=validate`) — 신규 `coupon` 테이블은 V5 마이그레이션 필수(엔티티가 테이블 생성 안 함).
- read DTO 3단(schemas.ts zod → api.ts fetch+parse → queries.ts hook), zod boundary loud-fail.
- 날짜 규칙: 이벤트는 datetime-local KST↔UTC(`kstLocalToUtcIso`/`utcIsoToKstLocal`). **쿠폰은 날짜만(LocalDate)** — KST 날짜 그대로 저장·표시, 시간대 변환 불필요(뉴스 날짜 슬라이스 표시와 유사한 정직성).

### Integration Points
- `AdminConsolePage`에 `CouponSection` 추가(EventSection·WatchlistSection 옆).
- `NewsPanel`에 쿠폰 섹션을 **맨 위**로 추가(useCoupons 소비, 독립 데이터지만 같은 카드 내 섹션).
- 공개 `CouponController` + `AdminCouponController`는 기존 컨트롤러 패턴 그대로.

</code_context>
