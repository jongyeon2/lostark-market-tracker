## Decisions Made
- **뉴스 날짜 = KST 로컬 슬라이스:** startDate/endDate/date는 오프셋 없는 ISO 로컬(KST wall-clock) → `newsDate()`가 문자열 앞 10자 슬라이스(YYYY.MM.DD). formatKst는 UTC 가정으로 +9h 시프트하므로 뉴스에 부적합 — 문자열 슬라이스가 정확/정직.
- **notice type 중립 뱃지:** findings대로 type은 불투명 한글(공지/점검/…) → enum 미잠금, `border`+`text-muted-foreground` 중립 뱃지로 값 그대로 표시.
- **독립 boundary:** NewsPanel과 물품 그리드가 각자 AsyncBoundary → 뉴스 실패가 물품을 안 가림(D-07). max-w-6xl 그리드가 폭 제어(좌 minmax(0,1fr) / 우 20rem).

## Deviations from Plan

**1. [Rule 3] api.ts 추가(플랜 files_modified 미포함)**
- **Found during:** Task 1 (기존 훅 패턴 확인)
- **Issue:** 플랜 Task 1 files_modified는 schemas.ts+queries.ts만. 그러나 코드베이스의 모든 React Query 훅은 `@/lib/api`의 fetch+zod-parse 함수를 감싼다(queries.ts엔 훅만). queryFn에 fetch를 인라인하면 이 분리 패턴을 깬다.
- **Fix:** 패턴 준수를 위해 `getNews()`를 api.ts에 추가(getItems/getEventImpact와 동형, `request()`+`newsResponseSchema.parse`). 플랜 인터페이스 노트의 "기존 fetch 헬퍼/훅 패턴대로"를 문자 그대로 이행.
- **Impact:** 파일 1개 추가 수정, 계약/스코프 불변. 코드베이스 일관성↑.

**2. [Rule 1] verify grep 주석 매칭 즉시 수정**
- **Issue:** Task 3 verify `! grep -q "max-w-3xl"`가 초기 주석 문구("former standalone max-w-3xl")의 리터럴에 걸림(실제 클래스는 제거됨).
- **Fix:** 주석에서 리터럴 토큰 제거("narrow item wrapper") → verify 통과. 레이아웃 코드 변화 없음.
