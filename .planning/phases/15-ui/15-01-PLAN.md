## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser/admin client → `/api/admin/**` gate | The new GET sits behind `AdminSecretFilter`; only a valid constant-time `X-Admin-Secret` reaches the controller |
| Controller → JPA → Postgres | `findAll()` reads every `tracked_item` row (including soft-deleted) and serializes it via `TrackedItemResponse` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1501-01 | Information Disclosure (soft-deleted rows exposed publicly) | new GET endpoint | mitigate | The endpoint is mounted under `/api/admin/items`, which `SecurityConfig` already maps to `.authenticated()`; the public `GET /api/items` is untouched and still returns active-only. A no-secret request 401s (asserted in Task 2), so inactive items never reach an unauthenticated caller. |
| T-1501-02 | Elevation of Privilege (accidental write via the read path) | AdminItemService.listAll | mitigate | `listAll()` calls only `findAll()` + an in-memory sort — no `save`/`delete`. An acceptance check + `git diff --stat` confirm no collection/cache/auth file changed (D-14). |
| T-1501-03 | Information Disclosure (over-exposure of entity internals) | TrackedItemResponse | accept | The response reuses the existing `TrackedItemResponse` projection (no entity leak, no price history) already shipped for POST — no new field surface is introduced. |
| T-1501-04 | Tampering (mass-assignment via reused DTO) | request binding | n/a | The endpoint is a GET with no request body — there is no bindable input to mass-assign. |
</threat_model>
