# Phase 17.4 스파이크 — 로스트아크 일별 시세 백필 소스

**Date:** 2026-07-07 (2026-07-07 정정: 각인서 관련 결론 수정)
**Endpoints:** `GET /markets/items/{id}` (상세) + `POST /markets/items` (리스트) — 실 API 호출, `.env` LOSTARK_API_KEY, HTTP 200
**목적:** 서버 off로 생긴 타임라인 수집 공백을, 로스트아크가 보관하는 일별 시세로 정직하게 백필할 수 있는지 확인.

---

## 정정 요지 (중요)

초기 결론 "각인서는 거래가 없어 백필 불가"는 **틀렸다**. 각인서는 활발히 거래되며(유물 원한 각인서 실측 min 145,500·135 스냅샷), 일별 평균가도 존재한다. 진짜 사실은 **일별 평균 소스가 2종이고 커버리지가 다르다**는 것:
- **상세 `Stats[]`**: 14일 이력이지만 **재료(50010)만** 채워지고 **각인서(40000)는 AvgPrice=0** (API가 각인서 상세 이력을 안 줌).
- **리스트 `YDayAvgPrice`**: **전일 1일치**지만 **각인서 포함 전 품목** 채워짐. 수집기가 이미 읽는 list 응답에 **무료**로 들어있음.

---

## (a) 상세 `Stats[]` 깊이 — 14일 연속

세 품목 모두 `Stats[]` length = **14**, 날짜 **06-24 ~ 07-07 (오늘 포함) 하루 1개씩 연속**.
- → 상세 소스 백필 범위 = 최근 14일. 14일 초과 gap은 상세로 복구 불가 → 장기 해결은 Phase 18 상시 배포. 백필은 보완.

## (b) 상세 `Stats[].AvgPrice` 채움 — 재료만

| 품목 | category | Stats | AvgPrice>0 | 실측 min(DB) | 비고 |
|------|----------|-------|-----------|------|------|
| 운명의 파괴석 결정 (66102007) | 50010 재료 | 14 | **14/14** | 1685 | 07-07 1732.3·TradeCount 4만~24만/일 |
| 아비도스 융화 재료 (6861012) | 50010 재료 | 14 | **14/14** | 128 | TradeCount 100만~450만/일 |
| 유물 원한 각인서 (65200505) | 40000 각인서 | 14 | **0/14** | **145,000** | 거래는 활발한데 상세 Stats만 0 (API 한계) |

- 재료는 상세 Stats 14일 전부 실 일별 평균가.
- **각인서는 상세 Stats가 0** — 거래가 없어서가 아니라 **API가 각인서 상세 일별 이력을 제공하지 않기 때문**. 실측 min은 정상(145K).

## (c) 리스트 `YDayAvgPrice` — 전 품목 전일 평균 (무료)

`POST /markets/items`(수집기가 이미 호출) 응답의 각 아이템에 `CurrentMinPrice`·**`YDayAvgPrice`(전일 평균)**·`RecentPrice` 포함:

| 품목 | CurrentMinPrice | **YDayAvgPrice** | RecentPrice |
|------|-----------------|------------------|-------------|
| 유물 원한 각인서 (65200505) | 145,500 | **147,007.4** | 145,498 |
| 유물 돌격대장 각인서 (65203305) | 145,700 | **146,190.4** | 145,700 |
| 유물 예리한 둔기 각인서 (65201005) | 140,999 | **141,133.6** | 140,999 |

- **YDayAvgPrice는 각인서 포함 전 품목 채워짐.** 단 전일 1일치 → 매 수집 시 저장하면 going-forward 일별 평균 시리즈를 전 품목으로 구축 가능. 추가 API 호출 0(list에 무료 동봉).
- 한계: 전일치만 → 다일 outage 시 마지막 하루만 소급, 그 이전은 못 채움.

## (d) 지표 불일치 — avg(거래) vs min(호가)

- `Stats.AvgPrice`/`YDayAvgPrice` = 일별 **거래** 평균가. `price_snapshot.min_price` = 실시간 **최저 호가**(`CurrentMinPrice`).
- 유동 품목은 근사(파괴석 avg 1732 vs min 1685)하나 **동일 지표 아님**. 타임라인에서 "실측 min vs 백필 일평균" **시각 구분** 필수(한 라인에 섞으면 경계서 인위적 단차).

## (e) 레이트리밋

- `x-ratelimit-limit: 100`, 1콜 후 remaining 98. YDayAvgPrice는 기존 list 호출에 무료 동봉(추가 0). 상세 Stats는 품목당 1콜(재료만, 저빈도) → 여유.

## 설계 함의 (17.4-CONTEXT.md D-01~로 확정)

1. **소스 2종 병행:** (a) 매 수집 시 `YDayAvgPrice` 무료 캡처 → 각인서 포함 전 품목 일별 평균 going-forward. (b) 상세 `Stats[]`로 재료 최근 14일 과거 gap 소급.
2. **저장:** 별도 `item_daily_stats(item_id, stat_date, avg_price, source)` 테이블(Task 0 예비안). `price_snapshot`(Core Value 가드)은 additive 무변경.
3. **표시:** 백필 일평균을 연속 라인으로, 실측 min_price는 그 위 표식으로 시각 구분(정직성). 한 라인 혼합 금지.
4. **트리거:** 서버 기동 시 + 일 1회(멱등 upsert). YDayAvgPrice는 수집 흐름에 편승, 상세 Stats 소급은 이 트리거.
5. **한계 명시:** 상세 14일·재료 소급 / YDayAvgPrice 전일치·전 품목. 14일 초과 다일 gap은 복구 불가 → Phase 18 상시 배포 보완.

## Exit-gate — **PASS**

- ✅ 일별 시세 백필 **가능**, 각인서 포함. 소스 2종(상세 14일 재료 / YDayAvgPrice 전일 전 품목)으로 커버리지 상보.
- ✅ YDayAvgPrice는 기존 수집 호출에 무료 → 저비용으로 전 품목 일별 평균 확보.
- ⚠️ avg(거래)≠min(호가) → 정직한 시각 구분 필수. 14일 초과 gap·각인서 다일 과거 gap은 여전히 불가.
