# Phase 28 UI-SPEC — 대시보드 통합 (`/gems`·`이벤트 영향` 흡수)

## 목표

흩어진 3화면을 **대시보드 하나로** 모은다. `/gems`는 6개 값을 보여주려고 페이지 하나를 썼고,
`이벤트 영향`은 페이지를 옮겨가 셀렉터로 품목을 **다시** 골라야 했다 — 대시보드에서 카드를 누르면
바로 아래 뜨는 편이 낫다(사용자 재설계 2026-07-15).

**신규 디자인 토큰 0 · 신규 색 0 · 신규 spacing 0.** 전부 기존 컴포넌트·토큰 재사용.
accent `blue-600`은 계속 focus-visible ring 전용(D-01).

## 🔑 스크롤 박스 높이 — 정확히 맞출 수 없다 (정직 고지)

사용자 요청: 박스 높이 = "소식 박스 **위 선** ~ **첫 진행중 이벤트 카드 아래**".
실측하면 지금 **417px**다. 하지만 **그 지점은 고정이 아니다**:

```
소식 카드 위 선          0px
  └ 헤더 "로스트아크 소식"
  └ 쿠폰 섹션            83px ← 관리자가 등록한 쿠폰 수만큼 늘어난다 (행당 ~44px, 최대 6행)
  └ 진행중인 이벤트      185px
     └ 첫 이벤트 카드    213 ~ 417px  ← 배너 썸네일 유무·제목 줄 수에 따라 ±
```

쿠폰이 1개일 때 417px, **6개(MAX_ROWS)면 ~637px**. CSS에는 "옆 컬럼 특정 요소의 아래에 맞춰라"가
없고(그리드 subgrid로도 다른 컬럼 내부 요소는 못 잡는다), JS로 측정해 맞추면 리사이즈·데이터 변경마다
재측정하는 레이아웃 코드가 생긴다 — **6개 값 정렬하자고 감수할 복잡도가 아니다.**

**결정: 고정 `h-[26rem]`(416px) — 실측 417px에 맞춘 근사값.** 쿠폰 수가 바뀌면 어긋나지만,
어긋남은 우측 패널 안에서만 보이고 중앙 박스는 항상 같은 높이라 화면이 흔들리지 않는다.
이 한계를 사용자에게 고지했고, 정확한 추적을 원하면 별도 논의한다.

## 모바일 (<lg)

세로 스택 순서 유지: **칩 탭 → 물품 → 이벤트 영향 → 소식**.
- 스크롤 박스 **고정 높이 해제**(`h-auto lg:h-[26rem]`) — 좁은 화면에서 중첩 스크롤은
  페이지 스크롤과 싸운다. 모바일은 그냥 페이지가 스크롤된다.
- 이벤트 영향은 `md` 미만에서 카드(`EventImpactCards`), 이상에서 표(`EventImpactTable`) — **현행 그대로**.

## 컴포넌트별 계약

### 1. `CategoryNav` — 단독 항목 지원 (수정)

지금은 `GROUP_ORDER`(각인서·재료)를 돌며 그룹별 leaf만 그린다. **보석은 그룹이 없다.**

- `Category.group` 타입: `CategoryGroup` → `CategoryGroup | null`
- 데스크톱: 그룹들을 먼저 그린 뒤, **`group === null`인 leaf를 그룹 헤더 없이** 같은 `NavLeaf`로 렌더.
  들여쓰기는 그룹 leaf와 같게 두되 위에 `space-y-4` 간격이 그대로 붙어 시각적으로 분리된다.
- 모바일 칩: **무변경** — 칩 행은 이미 그룹을 무시하고 leaf만 평평하게 그린다. 보석 칩이 자동으로 붙는다.
- `NavLeaf`·`Chip`·활성 표시·`aria-current` **전부 무변경**.

### 2. `categories.ts` — 보석 카테고리 (수정)

- `GEM_CATEGORY_ID = 'gems'` 상수. `deriveCategories(items, gemCount)`가 `gemCount > 0`일 때만
  `{ id:'gems', label:'보석', group:null, count:gemCount }`를 **맨 뒤에** 붙인다.
  (빈 leaf를 안 그리는 기존 규율 유지 — 보석 로딩 실패/0건이면 카테고리 자체가 없다.)
- `filterByCategory`는 **보석을 모른다** — `TrackedItem[]` 필터 함수이고 보석은 `TrackedItem`이 아니다.
  분기는 `DashboardPage`가 `selectedId === GEM_CATEGORY_ID`로 한다.

### 3. `GemCard` (신규) — 안 눌리는 카드

`ItemCard`와 **같은 가로 행 배치**(아이콘+이름 좌 / 가격 우)를 승계하되 **상호작용은 승계하지 않는다**:
`hover:shadow-md` 없음, `cursor-pointer` 없음, `<button>`·`<Link>` 아님 — 그냥 `<div>`.

- 이름: **`{level}레벨 {series}`** (예: "8레벨 겁화"). Phase 26에선 계열이 그룹 헤더에 있어서
  `displayName`이 "8레벨"만이었는데, 이제 그룹 헤더가 없으므로 카드가 계열을 직접 말해야 한다.
  **백엔드 계약은 안 바꾼다** — `series`·`level` 둘 다 응답에 이미 있으니 프론트가 조합한다.
- 가격: `GemPage`의 `GemPriceCell` 로직을 그대로 옮긴다 — `OK`면 🪙+골드, 아니면
  `즉시구매 매물 없음`/`잠시 후 다시`/`불러오지 못함`. **값을 지어내지 않는 규칙 유지.**
- 아이콘: `GemPage`의 `GemIcon`을 그대로 옮긴다(`ItemIcon`은 폴백 글리프가 `roleGroup`에 묶여 재사용 불가).
- 목록 위 라벨: **"현재 보석 시세값"** + 기준 시각(`기준 시각 {formatKst(updatedAt)}`).
  "1시간마다 갱신"이라고 **쓰지 않는다** — 기록 폴러는 DB용이고 이 화면은 여전히 온디맨드 캐시다.

### 4. `ItemCard` — 클릭 = 선택, 차트는 별도 링크 (수정)

**HTML 구조가 바뀐다.** 지금은 카드 전체가 `<Link>`인데, 그 안에 또 링크를 넣을 수 없다
(interactive 중첩 = 잘못된 HTML + 키보드 순서 깨짐). 두 형제로 나눈다:

```
<Card>
  <div class="flex">
    <button class="flex-1 ...">        ← 누르면 선택 (아래에 이벤트 영향)
      [아이콘][이름][역할뱃지] ... [🪙 최저가][수집 시각]
    </button>
    <Link to="/timeline?item={id}">    ← 차트로 이동 (형제, 중첩 아님)
      <LineChart 글리프> 차트
    </Link>
  </div>
</Card>
```

- 선택 상태: `aria-pressed` + `CategoryNav`의 활성 패턴 재사용
  (`border-primary` + `bg-muted`) — **색 단독으로 표시하지 않는다**(D-01 규율).
- 차트 링크는 `<Link>`라 Ctrl/가운데클릭 새 탭·키보드 Enter가 그대로 동작한다.
- 가격 fan-out(`useLatestPrice`)·`useCollectionHealth` 공유·`Skeleton`/`데이터 없음` 분기 **전부 무변경**.
- 카드 전체 hover elevation은 유지(이제 누를 수 있는 게 맞으므로 어포던스가 진짜다).

### 5. `DashboardPage` — 통합 오케스트레이션 (수정)

상태 2개(전부 로컬 `useState`, URL 동기화 없음 — Phase 23의 A4 YAGNI 규율 승계):
- `picked` (카테고리) — 기존
- `selectedItemId` (이벤트 영향 대상) — **신규**. **카테고리를 바꾸면 null로 리셋**한다.
  안 그러면 재료 카테고리를 보면서 아래엔 각인서 이벤트 영향이 남아 "무엇의 영향인지" 어긋난다.
- `window` (기간, 기본 24) — **신규**. `useImpactParams`(URL) 대신 로컬 state.

중앙 컬럼:
1. **스크롤 박스** — `lg:h-[26rem] overflow-y-auto`. 보석 카테고리면 `GemCard` 6장,
   아니면 `ItemCard` N장. **각 소스는 자기 `AsyncBoundary`를 가진다**(보석 실패가 물품을 안 가림, D-07).
2. **이벤트 영향 섹션** — `selectedItemId === null`이면 안내 한 줄
   ("물품을 선택하면 이벤트 전후 시세 변화가 여기에 표시됩니다"). 보석 카테고리면 **섹션 자체를 숨긴다**
   (보석은 선택이 불가능하므로 안내조차 거짓이 된다).

### 6. 삭제

- `frontend/src/features/gems/GemPage.tsx` — 내용은 `GemCard`로 이주
- `frontend/src/features/impact/ImpactPage.tsx` — 조립만 하던 껍데기. **내부 컴포넌트는 전부 생존**
  (`EventImpactTable`·`EventImpactCards`·`impactFormat`·`ImpactStatusBadge`·`CorrelationBanner`·`WindowControls`)
- 라우트 `/gems`·`/impact` → **`/dashboard`로 redirect**(`<Navigate replace>`). 북마크·기존 링크가
  404로 죽지 않게. `/timeline`은 유지.
- `TopNav`: `대시보드 | 품목 타임라인` 2개만 남는다.
- ⚠️ **삭제 전 사용처 확인 필요**: `useImpactParams`·`ItemSelect`·`LatestPriceCard`가 `ImpactPage`
  전용인지 `TimelinePage`도 쓰는지 `grep`으로 확인하고, 전용일 때만 지운다.

## 정직성 규칙 (전부 기존 규율 승계)

1. **보석 카드는 눌리게 생기지 않는다** — 갈 곳이 없으므로 가짜 어포던스를 만들지 않는다(Phase 26 판단).
2. **"1시간마다 갱신" 금지** — 화면은 온디맨드 캐시다. `기준 시각`만 말한다.
3. **상관 ≠ 인과 배너 유지** — `changeRate`는 시점 상관이지 인과가 아니다(PROJECT 전제 5).
4. **`insufficient_data`는 그대로 정직 표기** — `EventImpactTable`/`Cards` 내부 로직 무변경.
5. **가격 없음은 값을 지어내지 않는다** — 보석 3상태 문구 유지.
