# Phase 24 — 경매장 보석 카탈로그 스파이크 (AUCTIONS)

**Date:** 2026-07-15
**Endpoint:** `GET /auctions/options` + `POST /auctions/items` — 실 API, `.env` LOSTARK_API_KEY, HTTP 200
**How captured:** `AuctionsApiSpikeTest`(spike 프로파일, `@Disabled`) 4개 케이스 — 응답 원문을 UTF-8 파일
(`build/spike-auction-*.txt`)로 직접 기록. 총 ~20콜.
**목적:** 보석 현재가 둘러보기(GEM-02)를 계획하기 전, **경매장 API가 거래소와 무엇이 다른지**와
**"현재가"가 무엇인지**를 잠근다. 이 프로젝트가 경매장을 호출한 것은 이번이 처음이다.

> **보안 원칙(불변):** 실 JWT는 env(`LOSTARK_API_KEY`)에서만. `.env` gitignored·커밋 0.
> 이 문서에 키 미기재. 가격은 공개 시세이며 "현재가" 정의의 근거로만 인용(캡처 시점 스냅샷).

## 핵심 발견

1. **🔑 레이트리밋 버킷을 거래소와 공유한다** — `limit=100`·`reset` 타임스탬프가 동일하고, 경매장 호출
   직후의 거래소 호출이 **경매장 카운터에서 정확히 1 감소**했다. 보석 조회는 **10분 수집 예산을 그대로
   깎는다** → GEM-02에서 캐시는 선택이 아니라 **필수**.
2. **보석 = CategoryCode `210000`** (leaf, Subs 없음) — 옵션 트리에서 실측 확인.
3. **🔑 응답에 `Id`가 없다** — 거래소의 `Id`(= `external_item_id`, 워치리스트 PK)에 해당하는 필드가
   **부재**. 경매장 아이템은 **이름으로 식별**한다. 거래소 코드·스키마를 그대로 복사할 수 없는 이유.
4. **🔑 `Level`은 보석 레벨이 아니다** — 모든 보석이 `Level: 1640`(= 착용 아이템 레벨). 보석 레벨은
   **이름 안에**만 있다(`"8레벨 겁화의 보석"`). **숫자 레벨 필터가 없어** 레벨 지정은 `ItemName`으로만 가능.
5. **🔑 "현재가" = `AuctionInfo.BuyPrice`(즉시구매가)** — 다른 후보는 전부 오답이다(아래 §현재가 잠금).
6. **티어4 보석 = 겁화 + 작열이 전부** — 이름검색 `겁화` 1083 + `작열` 1136 = **2219** = 티어4 전체
   `TotalCount`와 **정확히 일치**(잔여 0). 다른 계열 없음.
7. `멸화`·`홍염` 티어4 = **0건** — 티어3 보석이라 이번 스코프 밖(가설 반증).
8. 아이콘은 거래소와 **같은 CDN·같은 경로**이고 보석별로 **전부 구별**된다(각인서처럼 공유하지 않음).

## H2 — 레이트리밋 버킷 공유 (Core Value 판정)

**1차 측정은 노이즈였다.** 내 호출 1건 사이에 remaining이 `85 → 53`(32 감소)으로 떨어졌다 —
**같은 키를 쓰는 다른 소비자**(운영 VM 수집기: 10분 틱 × 49품목)가 동시에 버킷을 태우고 있다.
스스로 움직이는 숫자로는 판정할 수 없어 **통제 측정**(연속 4콜, 사이 작업 0)을 다시 했다:

```
a1 AUCTIONS | limit=100 | remaining=94 | reset=1784096818
a2 AUCTIONS | limit=100 | remaining=89 | reset=1784096818
m1 MARKETS  | limit=100 | remaining=88 | reset=1784096818   ← 경매장 카운터에서 정확히 -1
a3 AUCTIONS | limit=100 | remaining=85 | reset=1784096818
```

**판정: 공유 버킷.** 근거 — (a) `m1`(거래소)이 `a2`(경매장) **바로 다음 값 88**을 받았다(별도 버킷이라면
거래소는 수집기가 이미 태운 자기 카운터를 따라 전혀 다른 값이어야 한다), (b) `limit`·`reset`이 넷 다 동일.

> ⚠️ **간섭은 여전히 있다**(a1→a2가 -5). 동시 소비자 + 슬라이딩 윈도우로 보이는 거동(1차 측정에서 같은
> reset 안에서 remaining이 60→72로 **증가**) 때문에 카운터는 정밀하지 않다. 하지만 **공유 판정은
> 보수적으로 안전한 쪽**이다: 실제로 분리인데 공유로 가정하면 캐시가 조금 과할 뿐이고, 실제로 공유인데
> 분리로 가정하면 **수집기를 굶긴다**(Core Value 훼손). 어느 쪽이든 **공유로 설계한다.**

**GEM-02 함의:** 보석 6종 조회 = **6콜/refresh**. 수집기는 10분마다 ~49콜을 쓴다(100/min 한도).
페이지뷰마다 무캐시로 6콜을 쏘면 트래픽에 비례해 수집 예산을 갉는다 → **온디맨드 + 캐시(TTL) 필수**,
설계 스펙이 "현재가 둘러보기(온디맨드+캐시)"로 못 박은 것이 실측으로 정당화됨.

> ### ⚠️ 정정 (2026-07-15, Phase 27 / GEM-04)
>
> **이 표에는 원래 `겁화(딜러)` · `작열(서포터)`라고 적혀 있었다. 그 역할 표기는 틀렸고, 측정한 적도 없다.**
>
> 이 스파이크가 실제로 측정한 것은 **이름 · 아이콘 · 등급 · 매물수 · 가격**뿐이다. 보석이 어떤 역할에
> 쓰이는지는 API가 알려주지 않으며 이 문서의 어떤 호출도 그것을 확인하지 않았다 — 내가 게임을 안다고
> 착각하고 **추측을 실측 표에 적었다.**
>
> 사용자(로아 유저) 정정: **보석은 역할로 나눠 쓰지 않는다.** 대부분 **레벨로 필터링해서 사고**,
> 인게임 재화(실링)로 원하는 스킬에 돌려 낀다. 보석 자체가 역할에 묶이지 않는다.
>
> 이 오류는 `GemCatalog.SERIES_DEALER` 상수와 `/gems` 화면 라벨로 그대로 전파됐다. 같은 문서가
> **"`Level`이 보석 레벨일 것이라는 가정을 실측으로 뒤집었다"**고 §H-반증에 기록하고 있는데,
> 잡아낸 것과 **똑같은 종류의 가정**이 바로 옆 표에 살아남아 있었다. **spike-then-lock은 API로 잴 수
> 있는 것에만 적용된다 — 게임 도메인 지식은 스파이크로 잴 수 없고, 물어봐야 안다.**
>
> **겁화/작열 구분 자체는 유효하다**(사용자 확인 2026-07-15): 값이 다른 별개 아이템이므로 나눠서
> 보여주는 게 맞다. 틀린 것은 역할 주석이지 계열 구분이 아니다.

- **아이콘 URL 패턴**: `https://cdn-lostark.game.onstove.com/efui_iconatlas/use/<file>.png` — 거래소와
  **동일 호스트·동일 경로**(Phase 12/21과 같음). 응답이 **전체 URL**을 그대로 준다.
- **아이콘 전부 distinct** — 각인서 18종이 `use_9_25`를 공유해 라벨 병기가 필요했던 문제(12-SPIKE D-06)가
  **여기선 없다**. 보석은 아이콘만으로 구별 가능.
- **등급이 레벨을 따라간다**: 8·9레벨=유물, 10레벨=고대 → 등급은 레벨의 파생이라 별도 표시 가치 낮음.

**티어4 전수 증명:** 겁화 `TotalCount=1083` + 작열 `TotalCount=1136` = **2219** = 무필터 티어4
`TotalCount=2219`. 잔여 0 → **티어4 보석은 겁화·작열 두 계열이 전부**이고 누락된 계열이 없다.

## 🔑 "현재가" 정의 잠금 (설계 스펙 line 135 미해결 질문)

경매장은 입찰 기반이라 거래소의 `CurrentMinPrice`처럼 자명한 "현재가"가 없다. 후보 4개를 실측했다:

| 필드 | 실제 의미 | 현재가로 쓸 수 있나 |
|---|---|---|
| `StartPrice` | 입찰 **시작가**(판매자가 정한 최저 입찰 출발점) | ❌ **위험** — 실측에 `StartPrice=1`, `StartPrice=22`가 있다(1골드 시작 입찰 미끼). 이걸 쓰면 **"9레벨 겁화의 보석 = 1골드"**로 표시된다 |
| `BidPrice` | **현재 최고 입찰가**. 입찰 0건이면 `0` | ❌ 대부분 `0`(`BidCount=0`) → "0골드"가 되거나 진행 중 경매에만 값이 있어 일관성 없음 |
| `BidStartPrice` | **다음 입찰 최소가**(현재가 아님, 미래 호가) | ❌ 사용자가 지금 지불하는 값이 아님 |
| **`BuyPrice`** | **즉시구매가** | ✅ **채택** — "지금 이거 사려면 얼마?"에 답하는 유일한 필드 |

**결정: 현재가 = `min(BuyPrice)` (즉시구매 가능한 최저가).**

- **거래소 `CurrentMinPrice`(최저 호가)와 의미가 대응된다** — 둘 다 "지금 즉시 살 수 있는 최저 금액".
  따라서 화면에서 거래소 품목과 **같은 '최저가' 어휘를 써도 정직하다**. (Phase 17.4의 min/avg 혼합 금지와
  같은 기준으로 검토한 결과 — 여기선 **혼합이 아니라 대응**이다.)
- **획득 방법**: `Sort=BUY_PRICE` + `SortCondition=ASC` + `PageNo=1` → **`Items[0].AuctionInfo.BuyPrice`**.
  1보석 = **1콜**. 6종 = 6콜.
- **⚠️ `BuyPrice`는 null일 수 있다** — 즉시구매를 안 걸고 입찰만 받는 매물이 존재한다(무필터 DESC 덤프에서
  `BuyPrice=None` 다수 확인). **ASC 정렬은 null을 뒤로 보낸다**(8~10레벨 이름검색 6건 전부 page1 null
  **0/10**, DESC에선 null이 앞에 옴) → ASC page1 첫 항목은 **항상 실제 최저 즉시구매가**다.
- **전 매물 null이면**(즉시구매 매물 0) → 현재가 **없음**으로 정직 표기. 값을 지어내지 않는다
  (event-impact `insufficient_data`·쿠폰 `startsAt` null과 같은 원칙).

**캡처 시점 최저 즉시구매가(증거·2026-07-15 15:23 KST):** 8레벨 겁화 347,000 · 9레벨 겁화 1,020,000 ·
10레벨 겁화 3,090,000 · 8레벨 작열 347,000 · 9레벨 작열 1,045,000 · 10레벨 작열 3,050,000.
(레벨이 오를수록 단가가 급등 — 값이 그럴듯하다는 sanity check.)

## 페이징·정렬

- `PageNo`는 **1-based**(`PageNo:1` 요청 → 응답 `PageNo:1`). `PageSize:10` 고정으로 관측.
- `TotalCount`는 **매물 건수**(품목 종류 수가 아님) — 8레벨 겁화 138개 매물 = 같은 보석의 개별 경매 138건.
- `Sort=BUY_PRICE`+`ASC`는 **정상 동작**(347000 → 347000 → 348000 …).
- ⚠️ `DESC`는 `BuyPrice=null` 매물이 **앞으로** 온다(무필터 DESC page1이 12600·344000·12358·4900로
  단조롭지 않음) → **DESC로 "최고가"를 구하지 말 것.** GEM-02는 ASC만 쓴다.

## GEM-02(구현)로 넘기는 제약

1. **캐시 필수** — 버킷 공유(§H2). 무캐시 온디맨드 금지.
2. **`Id`가 없다** — 워치리스트(`tracked_item.external_item_id`) 모델 재사용 불가. 보석은 **이름 키**.
3. **시계열 미기록** — `price_snapshot` 무변경(스코프 경계). 보석은 조회 전용.
4. **6콜/refresh** — 보석 1종당 1콜(이름검색). 배치 조회 수단 없음.
5. **거래소 클라이언트 재사용 금지** — 엔드포인트·body·응답 shape가 전부 다르다.
