# Quick Task 260723-jx1 — 타임라인 품목 선택: 드롭다운 → 2단 칩

## 무엇을 바꿨나

`ItemSelect`(Radix select, 49개 한 드롭다운) → **`ItemPicker`**(카테고리 칩 행 + 품목 칩 그리드).

**스크롤 헌팅이 사라졌고**(한 카테고리당 최대 11개), **선택한 품목명이 화면에 항상 떠 있게** 됐다.

## 지적받지 않았지만 같이 고친 것

기존 트리거는 **역할군 라벨만** 보여줬다:

```
[ 재료 ▾ ]   ← 실제로 보고 있던 건 "빙하의 숨결"
```

원래 주석의 진단은 맞았다 — *"a long engraving name otherwise overflows the compact trigger"*. 하지만 **넘치면 넓히거나 말줄임할 일이지, 이름을 지울 일이 아니었다.** 이번 교체로 자연히 해소됐다.

## 핵심 결정 · 근거

- **`categories.ts`를 `features/dashboard/` → `features/_shared/`로 이동.** 타임라인이 대시보드 내부 모듈을 import하면, 이 코드베이스가 `ItemSelect`에 대해 이미 세운 레이어 규칙(D-07: *"extracted to _shared so the layer dependency never flows impact→timeline"*)을 깬다. 두 화면이 공유하는 taxonomy가 됐으니 `_shared`가 제자리다.
- **보석 leaf를 만들지 않는다**(`deriveCategories(sorted, 0)`). 보석은 `TrackedItem`이 아니라 시계열이 없다 — 탭을 만들면 **그릴 수 없는 차트로 데려간다.** gemCount=0이면 leaf가 생성조차 안 되므로 별도 분기가 필요 없다.
- **🔑 로컬 state가 없다.** 활성 카테고리를 "선택된 품목이 속한 카테고리"로 매 렌더 유도한다. 카테고리를 누르면 그 카테고리의 첫 품목을 즉시 `onChange`하므로 `value`는 언제나 활성 카테고리 안에 있고, **둘이 어긋난 상태 자체가 존재할 수 없다.** `useEffect` 동기화가 필요 없고, 외부에서 `?item=`이 바뀌어도 자동으로 따라간다(대시보드 `selectedId` 유도와 같은 수법).
- **카테고리 클릭 = 첫 품목 자동 선택.** 차트는 `itemId`가 null일 수 없다(빈 화면 금지, `TimelinePage` D-06과 같은 원칙). 아무 일도 안 일어나면 활성 칩 없는 상태가 되어 오히려 더 헷갈린다.
- **`기타` 카테고리를 남겼다.** 지금은 비어 있다(실측: 11+7+31 = 49 = 전체, 누락 0). 그래도 두는 이유는 `ItemSelect`가 명시적으로 보장하던 것이기 때문 — *"NO curated item is ever dropped (ICON-07)"*. 시드가 늘어 분류가 밀릴 때 물품이 조용히 사라지는 대신 여기 뜬다.
- **`ItemSelect.tsx` 삭제.** `/impact` 페이지가 사라진 뒤(Phase 28) 유일한 소비자가 `TimelinePage`였다. 안 쓰는 선택기를 남기면 다음 사람이 둘 중 뭘 쓸지 고민한다.
- **컨트롤 바를 세로로 쌓았다.** 선택기가 한 줄에서 2단으로 자라므로 기간 컨트롤과 같은 줄에 두면 칩이 늘 때 날짜 입력이 밀린다. `[품목] / [기간]` 순서는 고르는 순서(무엇을 → 언제)와도 맞는다.

## 알려진 대가
