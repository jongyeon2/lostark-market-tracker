# Phase 17.4: 타임라인 gap 백필 — 일별 Stats - Context

**Gathered:** 2026-07-07
**Status:** Ready for planning

<domain>
## Phase Boundary

서버 off로 생긴 **품목 타임라인의 수집 공백**을, 로스트아크가 제공하는 **일별 평균가**로 별도 "일별 평균" 시리즈로 정직하게 백필해, 어떤 기간을 선택해도 그 기간의 시세가 연속으로 보이게 한다. **타임라인 화면 한정** — 대시보드(10분 실측)·이벤트 영향은 이 phase 밖.

경계 앵커: 새 백필 데이터 계층(수집 편승 캡처 + 소급) + 저장 테이블 + 타임라인 read/차트 병합. `price_snapshot`·수집/캐시/event-impact 로직은 **무변경(additive)**.
</domain>

<decisions>
## Implementation Decisions

### 백필 소스 (스파이크로 확정)
- **D-01:** 일별 평균 소스 **2종 병행**한다.
  - (1) **`YDayAvgPrice` 무료 캡처** — 수집기가 이미 호출하는 리스트(`POST /markets/items`) 응답의 전일 평균가. **각인서 포함 전 품목** 채워짐(유물 원한 각인서 147,007 확인), **추가 API 호출 0**. 매 수집 시 저장해 going-forward 일별 평균을 전 품목으로 축적.
  - (2) **상세 `Stats[].AvgPrice`** — 상세(`GET /markets/items/{id}`) 최근 **14일** 일별 평균. **재료(50010)만** 채워짐(각인서는 상세 Stats=0 = API 한계, 거래 없음 아님). 재료의 과거 gap 소급 채움.
- 정정 사항: 초기 "각인서 거래 없어 백필 불가"는 오류. 각인서는 활발히 거래(실측 145K)되며 YDayAvgPrice로 백필 가능. 상세 Stats만 각인서를 0으로 준다.

### 표시 방식
- **D-02:** 백필 **일평균을 연속 라인**으로 그리고(사용자가 원한 연속 뷰), **실측 min_price는 그 위에 시각적으로 구분**해 표식(점/색)한다. `min_price`(실시간 최저 호가)와 백필 `avg`(일별 거래 평균)를 **한 라인에 혼합 금지** — 경계에서 인위적 단차(예: 실측 1685 → 백필 1732 지표 전환 점프)가 생겨 오해를 준다. 지표가 다름을 정직하게 표기.

### 트리거
- **D-03:** 백필 실행 = **서버 기동 시 + 일 1회**(멱등 upsert). `YDayAvgPrice`는 매 수집(10분)에 편승 캡처, 상세 `Stats[]` 재료 소급은 이 트리거로. 재기동마다 최근 14일 재료를 채우고, 상시 운영 시 매일 갱신.

### 노출
- **D-04:** 백필은 **항상 표시**(기본 켜짐 — 사용자 목적=연속 뷰). 타임라인 **기본 조회 범위는 30일 유지**(백필 14일 + 실측 포함). 토글/90일 확대는 미채택.

### 저장 (스파이크 예비안 — 세부는 planner)
- **D-05:** 별도 **`item_daily_stats`**(item_id, stat_date, avg_price, source) 테이블에 additive 적재(Task 0 예비안). **`price_snapshot` 스키마·수집/캐시/event-impact 로직 0줄**(Core Value 가드). Flyway 다음 순번 V6.

### Claude's Discretion
- `item_daily_stats` 정확한 컬럼/인덱스/유니크 키, upsert(멱등) 구현.
- 차트 렌더 세부: 백필 라인 스타일(색/점선), 실측 표식 형태, 툴팁/범례 문구("백필·일평균·거래가" 등 정직 라벨).
- `YDayAvgPrice`를 `PriceCollector`/`ItemFetchService` 흐름에 편승시키는 방식 + `MarketItem` DTO에 `YDayAvgPrice` 매핑 추가.
- 상세 Stats 소급 대상(재료) 판정 기준: `category=50010` vs `roleGroup=MATERIAL` 중 택.
- 타임라인 read에서 백필 시리즈를 `/api/items/{id}/prices` 응답에 병합할지 별도 엔드포인트로 둘지.
</decisions>

### Established Patterns
- **Core Value 가드**: 수집/캐시/event-impact·`price_snapshot`은 additive만(무변경). 신규 도메인은 별도 테이블/경로.
- **Flyway 마이그레이션**: V1–V5 immutable, 다음 순번 **V6**로 `item_daily_stats` 신설. JPA `ddl-auto=validate`.
- **정직성**: 조작 데이터 금지, 지표/출처 정직 표기(상관≠인과 배너 계열).
- **`TrackedItem.roleGroup`**(DEALER/SUPPORT/MATERIAL) + `category`(50010 재료 / 40000 각인서) — 상세 Stats 소급 대상 판정에 재사용.

### Integration Points
- 수집: `PriceCollector`가 `LostarkApiClient` list 응답을 처리하는 흐름에 YDayAvgPrice 저장 편승.
- 소급: 기동/일 1회 러너(예: `@Scheduled` 또는 ApplicationRunner)가 재료에 상세 `GET /markets/items/{id}` 호출 → `item_daily_stats` upsert.
- read: `/api/items/{id}/prices`(또는 신규 엔드포인트)가 `item_daily_stats`를 타임라인 시리즈에 병합 → 프론트 `PriceTimelineChart`가 백필 라인 + 실측 표식으로 렌더.
