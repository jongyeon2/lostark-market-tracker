# Quick Task 260719-wl0 — 대시보드 헤더/네비 다듬기

배포된 대시보드를 라이브로 보며 다듬은 프론트 폴리시 묶음. 프론트만(`frontend/src`), 백엔드 0줄,
데이터 흐름·API 무변경. 최초 3건으로 시작해 사용자 라이브 QA를 여러 번 거치며 좌측 레이아웃이
"공지 이동 → 흰 카드 → 좌우 대칭 → 두 박스 분리"로 수렴했다.

## 무엇을 바꿨나 (최종 상태)

- **헤더 좌우 이동 제거(버그):** `index.css`에 `html { scrollbar-gutter: stable }`. 페이지 길이에 따라
  세로 스크롤바가 생겼다 사라지며 가용 폭이 ~15px 바뀌어, `mx-auto` 중앙정렬(AppLayout·TopNav)이
  라우트 전환마다 좌우로 튀던 문제. 스크롤바 자리를 상시 예약해 폭을 고정.
- **보석 카테고리 아이콘:** `CategoryNav`의 보석 단독 leaf(그룹 헤더가 없어 아이콘을 못 받던)에
  lucide `Gem` 글리프. 재료 `Hammer` 선례와 동일한 "대체 글리프" 방식.
- **공지사항 좌측 이동:** 우측 `NewsPanel`에서 공지를 `NoticeRail`로 분리(export). 자체 `useNews` +
  자체 `AsyncBoundary`라 소식 실패가 카테고리·쿠폰·이벤트를 가리지 않는다(D-07 격리 유지). React
  Query가 `useNews` 캐시를 공유하므로 좌/모바일 두 곳에 마운트돼도 요청은 한 번.
- **우측 소식 박스:** "로스트아크 소식" 제목 제거(각 섹션 헤딩이 이미 라벨). 제목 제거 뒤 남던
  상단 이중 패딩(Card `py-6` + CardContent `pt-6` = 48px)에서 `pt-6` 제거 → 쿠폰이 위로.
- **공지 제목 1줄:** `line-clamp-1` — 넘치면 `…`. 2줄이면 줄글처럼 읽힌다는 피드백.
- **좌측 = 우측과 대칭 흰 카드:** 좌측 열을 우측 소식 박스와 **동일한 20rem·p-6 흰 카드**로. 이어
  카테고리/공지를 **별개 카드 2개**로 분리(구분선 제거) — 한 박스에 둘을 넣으니 불편하다는 피드백.
- **컬럼 간격:** `lg:gap-12`(32→48px).
- **페이지 폭:** 좌우 20rem 대칭으로 중앙이 좁아져(640px@1440) "이벤트 영향" 테이블(754px)이 가로
  스크롤되던 것을 없애기 위해 `AppLayout`·`TopNav`의 `max-w` **90rem→100rem**(중앙 ~800px, 넓은
  화면 기준 무스크롤). TopNav는 본문과 정렬돼야 하므로 항상 같은 값(주석 명시).

## 핵심 결정 · 근거

- **sticky 소유를 CategoryNav→DashboardPage로 이관:** 필터만 sticky이고 공지가 그 아래 흐르면 스크롤
  시 공지가 배경 없는 고정 필터 "뒤로" 겹친다. 좌측(카테고리 카드+공지 카드)을 한 sticky 블록으로
  묶어(`space-y-6`) 통째로 고정 → 겹침 없음.
- **카드는 lg 전용(`lg:*`)으로만:** 데스크톱은 흰 박스, 모바일은 카드 없이 칩 행이 edge-to-edge로
  그대로 노출. 공지는 lg에선 좌측 카드, 모바일에선 `NewsPanel` 하단의 자체 Card로 내려간다(칩→물품
  →영향→쿠폰·이벤트→공지 순서 유지).
- **좌측 폭을 우측과 동일(20rem)로:** 11rem은 답답하다는 라이브 피드백(그 대가가 페이지 폭 확대).
  폭까지 대칭이라 중앙이 좁아지는 것을 `max-w` 확대로 흡수 — 80rem→90rem 때(이벤트 테이블 수용)와
  같은 논리를 100rem으로 이어감.
