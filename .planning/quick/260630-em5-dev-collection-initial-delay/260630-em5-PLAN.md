# Quick 260630-em5: dev 프로파일 첫 수집 타이밍 버그 수정

## 문제 (재현됨)

dev 프로파일로 실시간 수집을 처음 돌렸을 때 모든 품목 카드가 "최신가 아직 없음"으로 표시됨.
`price_snapshot` 0건, `tracked_item`(active) 15건, `collection_run` 1건이 `items_attempted=0`,
`items_succeeded=0`, `status=SUCCESS`로 기록됨.

## 근본 원인 (측정 기반)

- dev는 `collection.initial-delay-ms`를 오버라이드하지 않아 `PriceCollector`의 기본값 `0`이 적용됨
  (`@Value("${collection.initial-delay-ms:0}")`, `fixedDelay=600000`).
- Spring 생명주기상 `@Scheduled` 스케줄러는 `finishRefresh` 단계에서 시작되고,
  `WatchlistSeeder`(`ApplicationRunner`)는 그 직후 `callRunners` 단계에서 실행됨.
- initial-delay=0이라 **첫 틱이 시더보다 먼저** 돌아 `tracked_item`이 빈 상태에서 `findByActiveTrue()`가
  빈 리스트 → `items.size()=0` → `succeeded(0)==items.size(0)`이라 SUCCESS로 오기록 → 스냅샷 0건.
- 다음 실제 수집은 fixedDelay 10분 뒤라, 그 사이 화면이 비어 보임.
- seed 프로파일은 `initial-delay-ms: 3600000`(1h)이라 이 문제가 가려져 있었음(합성 데이터가 화면을 채움).

## 수정 (단일 태스크)

**Task 1 — `src/main/resources/application-dev.yml`에 `collection.initial-delay-ms: 10000` 추가**
- 시더가 워치리스트 15개를 upsert한 뒤 첫 틱이 돌도록 초기 지연(10초)을 줌.
- `fixedDelay`(10분)는 그대로 유지 — 첫 틱만 지연.
- 범위: dev 프로파일 한정. seed/test(이미 1h)·기본(application.yml) 무변경. Java 코드·DB 무변경.

## 검증

- **정적:** 키가 `PriceCollector`의 `@Value` 키 및 `application-seed.yml`의 `collection.initial-delay-ms`와
  동일 구조·동일 키임을 확인.
- **런타임(핵심):** 백엔드를 dev 프로파일로 재시작한 뒤 `collection_run`에 `items_attempted=15`가
  기록되는지 확인(키가 유효하면 `items_succeeded=15`, `price_snapshot>0`, 카드에 실제 시세 표시).
