# Phase 27-02 — `/gems` 정정: 역할 라벨 제거 + 레벨 중심 표 (GEM-04)

## 무엇이 틀렸나

`/gems`는 보석을 **겁화 (딜러)** / **작열 (서포터)** 두 그룹으로 나눠 보여준다. **그 괄호는 틀렸다.**

사용자(로아 유저) 정정(2026-07-15): 보석은 역할별로 나눠 쓰지 않는다. 대부분 **레벨로 필터링해서 사고**,
인게임 재화(실링)로 원하는 스킬에 돌려 끼운다. 즉 보석 자체가 역할에 묶이지 않는다.

**이 오류의 성격이 나쁘다.** Phase 24 스파이크가 실제로 측정한 것은 이름·아이콘·등급·매물수·가격뿐이고
**역할은 측정한 적이 없다.** 그런데 `24-SPIKE-FINDINGS.md`의 카탈로그 표에 `겁화(딜러)`라고 적혀
근거 있는 실측처럼 굳었고, `GemCatalog.SERIES_DEALER`라는 상수명과 화면 라벨로 전파됐다.
같은 스파이크가 **`Level`이 보석 레벨일 것이라는 가정을 실측으로 뒤집었다고 자랑하는 문서**에서
벌어진 일이다 — 잡아낸 가정과 **똑같은 종류의 가정**이 옆줄에 살아남았다.

**그래서 화면만 고치고 끝내지 않는다.** findings 문서가 이 프로젝트의 "보석 사실" 원본이므로 거기서
고치지 않으면 다음 phase가 같은 라벨을 다시 퍼온다.

**단, 겁화/작열을 합치지는 않는다.** 둘은 서로 다른 아이템이고 가격도 다르다(9레벨 기준 1,038,888 vs
1,069,997 — 실측). 역할 주석이 틀렸다는 것이 두 계열이 같다는 뜻은 아니다.

## 설계 결정

**레벨 중심 표.** "레벨로 필터링해서 산다"가 사용자의 실제 사고 축이므로 레벨이 행이 된다.
계열이 열이 되면 6개 값이 3행에 들어가고, **같은 레벨의 겁화 vs 작열 비교가 가로로 바로** 된다
(현재 2그룹 6행 세로 나열에서는 눈이 6행을 왕복해야 한다). 역할 그룹 헤더가 사라져 생기는
빈 공간 문제도 이 배치가 같이 푼다.

```
          겁화          작열
8레벨    🔹 346,888    🔹 348,798
9레벨    🔹 1,038,888  🔹 1,069,997
10레벨   🔹 3,060,000  🔹 3,050,000
```

아이콘은 셀 안에 남긴다 — 6종이 전부 distinct한 실 CDN 아이콘이고(24 실측), 축(레벨·계열)이
글자로 말하는 것을 아이콘이 그림으로 확인해 준다.

**행·열을 데이터에서 파생한다.** `[...new Set(gems.map(g => g.level))]`·`(g => g.series)`로 축을 만든다.
프론트가 `['겁화','작열']`을 하드코딩하면 **카탈로그의 진실 원본이 둘로 갈라진다** — 백엔드가 계열을
추가·개명해도 화면이 모른다. Phase 26이 계열 순서를 백엔드에서 받아온 규율의 연장이다.

**`SERIES_LABEL` 매핑을 삭제한다.** 그 Record는 백엔드 계열명을 화면 문구로 번역하려고 존재했는데,
번역할 내용이 틀린 추측이었다. 계열명을 **그대로** 쓰면 매핑이 필요 없고 하드코딩도 사라진다.

**"1시간마다 갱신"이라고 쓰지 않는다.** 27-01이 기록 폴러를 켜지만 그건 **DB 기록**이고, 화면이 읽는
건 여전히 온디맨드 캐시다. 폴러가 생겼다고 서빙 문구를 바꾸면 Phase 26이 지운 그 거짓말이 다른
숫자로 돌아온다. `기준 시각`을 유지한다.

### Task 2 — `/gems` 레벨 중심 표

**name:** 레벨 중심 표 재구성
**action:** `GemGroup`/`GemRow`/`SERIES_LABEL` 제거, 시맨틱 `<table>` 도입. `GemIcon`·`GemPriceCell`·
`AsyncBoundary`·Card·`formatKst`는 **그대로 재사용**(신규 토큰·신규 색·신규 spacing 0).

**files:**
- `frontend/src/features/gems/GemPage.tsx` (수정)

- `<table>` + `<thead>`(빈 코너 셀 + 계열별 `<th scope="col">`) + `<tbody>`(행마다
  `<th scope="row">{level}레벨</th>` + 계열별 `<td>`). 스크린리더가 "9레벨 / 작열 / 1,069,997"로
  읽도록 축을 `<th>`로 준다 — `<div>` 격자로는 못 하는 것.
- 셀 조회: `gems.find(g => g.level === level && g.series === series)`. 카탈로그에 없는 조합이면
  셀을 비운다(6종이 항상 오지만 화면이 계약을 신뢰하되 의존하지는 않는다 — Phase 26 규율).
