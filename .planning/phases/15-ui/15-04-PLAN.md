## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin add-form input → adminRequest → `/api/admin/items` | externalItemId/displayName/category cross to the backend behind the secret gate; the backend @Valid + upsert branch is the authority |
| `GET /api/admin/items` (active+inactive) → console | Soft-deleted rows are exposed to the authenticated admin only — never to the public read surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1504-01 | Denial (accidental removal from the collector) | deactivate flow | mitigate | 비활성 requires the D-09 inline 2-step confirm ('…수집 대상에서 제외됩니다.'); and it is a SOFT delete (backend D-03) — the row + price history survive and 재활성 restores it, so no data is destroyed. |
| T-1504-02 | Information Disclosure (inactive items leak to public) | getAdminItems | mitigate | Inactive rows come ONLY from `GET /api/admin/items` behind the admin gate (15-01); the public `GET /api/items` stays active-only. A 401 blocks unauthenticated access (15-01 test). |
| T-1504-03 | Elevation of Privilege (mass-assign id/active) | AdminItemRequest | mitigate | The client sends only `{externalItemId, displayName, category}`; the backend binds `TrackedItemRequest` (not the entity), so `id`/`active` cannot be set from the body — reactivation goes through the controlled upsert, not a client-set flag. |
| T-1504-04 | Confusion (duplicate add silently fails) | 409 handling | mitigate | An active-duplicate 409 is special-cased to the clear '이미 활성 상태인 품목이에요.' warning instead of a generic error, so the admin understands the item already exists. |
| T-1504-05 | Information Disclosure (schema drift) | trackedItemsSchema | mitigate | The admin-items response is `.parse`d with the existing `trackedItemsSchema`; drift fails loudly into `AsyncBoundary`'s ErrorState rather than rendering a malformed row. |
</threat_model>
