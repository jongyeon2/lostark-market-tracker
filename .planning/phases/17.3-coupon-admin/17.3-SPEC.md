# Phase 17.3: 쿠폰 관리자 등록 — Specification

**Created:** 2026-07-06
**Ambiguity score:** 0.19 (gate: ≤ 0.20)
**Requirements:** 4 locked

## Goal

관리자가 콘솔에서 로스트아크 쿠폰(코드·보상·만료일)을 등록·수정·삭제하면, 그 쿠폰이 PostgreSQL에 영속되고 대시보드 뉴스 패널의 '쿠폰' 섹션에 미만료 쿠폰만 만료임박순으로 표시되며(코드 원클릭 복사), 만료된 쿠폰은 공개 목록에서 자동 제외된다.

## Background

관리자 쓰기 스택(엔티티 → Flyway 마이그레이션 → repository → `Admin*Controller`(X-Admin-Secret 게이트) → 프론트 admin 섹션)은 이벤트(`GameEvent`/`AdminEventController`/`EventSection`)와 워치리스트(`TrackedItem`/`AdminItemController`/`WatchlistSection`)에 이미 완성돼 있다. 공개 read 컨트롤러 패턴(`/api/...`, SecurityConfig `anyRequest().permitAll()`), 프론트 read 3단(`schemas.ts` zod → `api.ts` fetch+parse → `queries.ts` hook), 대시보드 뉴스 패널(`NewsPanel.tsx`, 이벤트+공지 섹션)도 존재한다.

**부재(이번 델타):** `Coupon` 엔티티·`V5` 마이그레이션·`CouponRepository`·`AdminCouponController`·공개 `CouponController`·admin 쿠폰 UI·대시보드 쿠폰 섹션 — **전부 신규**. 쿠폰은 Phase 17.2(NEWS)에서 "공식 API 부재 → 이후 관리자 수동 입력"으로 명시적 defer됐고, 이 페이즈가 그 수동 입력 경로를 실현한다. 뉴스(휘발성 Redis 캐시)와 달리 쿠폰은 관리자 입력 데이터라 **PostgreSQL 영속**이 필요하다.

## Requirements

1. **쿠폰 영속 + 관리자 CRUD**: 관리자가 쿠폰을 목록으로 보고 등록·수정·삭제할 수 있고, 데이터는 PostgreSQL에 영속된다.
   - Current: `Coupon` 엔티티/테이블/컨트롤러가 없다 — admin CRUD는 `GameEvent`·`TrackedItem`에만 존재
   - Target: `Coupon` 엔티티(code·reward·expiresAt) + Flyway `V5__add_coupon.sql`; `GET/POST/PUT/DELETE /api/admin/coupons`가 X-Admin-Secret 게이트로 동작(`AdminEventController` 패턴 미러링), JPA `ddl-auto=validate` 통과
   - Acceptance: admin IT — X-Admin-Secret로 POST 생성(201)→GET 목록 포함→PUT 수정→DELETE 제거가 동작하고, 시크릿 없는 요청은 401

2. **공개 쿠폰 서빙 + 만료 자동 숨김**: `GET /api/coupons`가 미만료 쿠폰만 만료임박순으로 공개 반환한다.
   - Current: 공개 쿠폰 엔드포인트가 없다
   - Target: 공개 `GET /api/coupons`(permitAll)가 `expiresAt >= now` 쿠폰만 만료임박순(ascending)으로 반환하고 만료 쿠폰은 제외; admin 목록에는 만료 쿠폰도 유지
   - Acceptance: IT — 유효 2 + 만료 1 시드 시 `GET /api/coupons`가 유효 2개만 만료임박순으로 반환, 만료 1개는 부재

3. **관리자 쿠폰 관리 UI**: 관리자 콘솔에 쿠폰 섹션이 있어 목록·등록·수정·삭제가 가능하다.
   - Current: 콘솔에 `EventSection`/`WatchlistSection`/`CollectionSection`만 있고 쿠폰 섹션이 없다
   - Target: `CouponSection.tsx`(AdminConsolePage에 배치) — 목록 + 등록 폼(code/reward/expiry) + 인라인 수정 + 삭제, 기존 admin mutation 패턴(X-Admin-Secret 자동 첨부·onSuccess invalidate) 재사용
   - Acceptance: 콘솔에 쿠폰 섹션 렌더; 폼으로 쿠폰 등록 시 목록에 나타나고, 수정·삭제가 목록에 반영; `npm run build` 그린

4. **대시보드 쿠폰 섹션**: 뉴스 패널에 유효 쿠폰이 만료임박순(≤6)으로 표시되고 코드를 원클릭 복사할 수 있으며, 없거나 실패해도 정직히 표시된다.
   - Current: `NewsPanel`은 진행중 이벤트·공지사항 2섹션만; 쿠폰 섹션이 없다
   - Target: `NewsPanel`에 3번째 '쿠폰' 섹션 추가 — `useCoupons()`(GET /api/coupons) 소비, 각 행 code·reward·만료일 + 원클릭 코드 복사 버튼(clipboard), ≤6·만료임박순, 로딩/빈/에러는 기존 `AsyncBoundary`
   - Acceptance: 쿠폰 존재 시 섹션이 목록 표시 + 복사 버튼이 클립보드에 코드 기록; 없으면 정직한 빈 문구; 프론트는 `/api/coupons`만 호출(로아 직접 호출 0); `npm run build` 그린

## Boundaries

**In scope:**
- `Coupon` 엔티티 + PostgreSQL Flyway 마이그레이션 + `CouponRepository`
- 관리자 CRUD API `/api/admin/coupons`(X-Admin-Secret) — 목록·등록·수정·삭제
- 공개 `GET /api/coupons`(미만료·만료임박순)
- 관리자 콘솔 쿠폰 섹션(CRUD UI)
- 대시보드 뉴스 패널 쿠폰 섹션(코드 복사·≤6·만료임박순·정직한 상태)

**Out of scope:**
- 쿠폰 자동 수집/스크래핑 — 공식 쿠폰 API 부재; 관리자 수동 입력만 (원래 defer 사유)
- 쿠폰 사용/소진(redemption) 추적 — 실제 사용은 게임 내 로아가 처리; 데모는 정보 표시만
- 쿠폰 코드 유효성 검증(로아 API 확인) — 검증 API 없음; 관리자 입력을 신뢰
- 사용자별 복사/클릭 통계·분석 — 데모 범위 밖
- 쿠폰 이미지/썸네일 — 텍스트 표시로 충분(이벤트 배너와 달리 쿠폰은 배너 없음)
- 만료 임박 D-day 뱃지 정교화 — 우선순위 낮음(만료임박순 정렬로 충분)

## Constraints

- **PostgreSQL 영속**: 뉴스(휘발성 Redis)와 달리 관리자 입력 데이터는 재시작에도 유지 — Flyway 마이그레이션으로 스키마 관리(JPA `ddl-auto=validate` 유지, 엔티티가 스키마를 만들지 않음)
- **Core Value 가드**: 수집(`PriceCollector`)·`CollectionConfig`·가격 캐시(`LatestPriceCache`)·`EventImpactService` 로직 0줄 — 쿠폰은 독립 도메인
- **인증 경계**: admin 쓰기는 기존 X-Admin-Secret 게이트 재사용, 공개 read는 permitAll(SecurityConfig `anyRequest().permitAll()` → `/api/coupons` 자동 공개, SecurityConfig 무변경)
- **프론트 가드**: 프론트는 백엔드 `/api/coupons`·`/api/admin/coupons`만 소비 — 로아 직접 호출 없음(상시 가드)
- **신규 의존성 0**: 기존 Spring Data JPA/RestController/React Query/zod 재사용
- **시간 기준**: 만료 비교는 서버 시각(UTC) 기준; 표시는 기존 날짜 포맷 규칙 준수

## Acceptance Criteria

- [ ] `Coupon` 엔티티 + Flyway 마이그레이션으로 code/reward/expiresAt가 PostgreSQL에 영속되고 `./gradlew build`의 JPA validate가 통과한다
- [ ] `POST/PUT/DELETE /api/admin/coupons`가 X-Admin-Secret 없으면 401, 있으면 CRUD가 동작한다 (admin IT 통과)
- [ ] `GET /api/coupons`가 미만료 쿠폰만 만료임박순으로 반환하고 만료 쿠폰은 제외한다 (IT 통과)
- [ ] 관리자 콘솔에 쿠폰 섹션이 있고 등록→목록 반영, 수정·삭제가 동작한다
- [ ] 대시보드 뉴스 패널에 유효 쿠폰이 ≤6·만료임박순으로 표시되고, 코드 복사 버튼이 클립보드에 코드를 기록한다
- [ ] 쿠폰이 없거나 로딩 실패해도 대시보드가 빈 화면 없이 로딩/빈/에러를 정직히 표시한다
- [ ] 프론트에 로아 직접 호출 0, 수집/캐시/event-impact diff 0줄 (Core Value 가드)
- [ ] `./gradlew build`와 `cd frontend && npm run build`가 모두 그린이다
