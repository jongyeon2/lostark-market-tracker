# Phase 17.2 Plan 02: 백엔드 뉴스 파이프라인 Summary

## Decisions Made
- **인바운드 vs 아웃바운드 네이밍 분리:** Lostark 응답은 PascalCase(Title/StartDate…), 프론트 계약은 camelCase(title/startDate…). record는 camelCase로 두고, client 전용 ObjectMapper(`UPPER_CAMEL_CASE`)로만 인바운드 매핑 → `@JsonProperty` 없이 양방향 계약 동시 충족.
- **미사용 소스 필드 관용:** `RewardDate`는 표시 DTO에서 제외 — `FAIL_ON_UNKNOWN_PROPERTIES=false`로 무시(향후 스키마 추가에도 read-path 무파손).
- **StringRedisTemplate + 주입 ObjectMapper:** 신규 캐시 config 빈 없이(7파일 제약) 기존 StringRedisTemplate + Boot ObjectMapper로 JSON 직렬화 — 가격 캐시(LatestPriceCache)의 RedisTemplate와 독립.

## Deviations from Plan

### 전제 정정 (17.1-01 D-04 정정과 동형)
**1. [Rule 2] 게이팅 방식: "실수집 @Profile" → initial-delay-ms config**
- **Found during:** Task 1/2 (PriceCollector/ApiClientConfig 실 패턴 확인)
- **Issue:** 플랜은 "LostarkNewsClient·NewsPoller를 PriceCollector와 동일 @Profile(실수집)로 게이트"를 전제했으나, **PriceCollector·ApiClientConfig에는 @Profile이 없다.** 실제 코드베이스는 `@Scheduled`를 프로파일이 아니라 `collection.initial-delay-ms`(test에서 3600000)로 발화 억제하고, 실 client는 IT에서 @MockitoBean으로 대체한다.
- **Fix:** 동일 실 패턴을 미러링 — NewsPoller는 `news.initial-delay-ms`(application-test.yml에서 3600000)로 테스트 중 발화 억제, LostarkNewsClient는 IT에서 @MockitoBean. `@Profile` 미사용.
- **Impact:** 결론 동일(테스트에서 라이브 호출 0·CI 안전), 코드베이스 일관성↑. 스코프 변화 없음.

**2. [Rule 3] SecurityConfig 무변경으로 공개 달성**
- **Issue:** 플랜은 "필요 시 /api/news permit" 여지를 뒀으나, SecurityConfig가 이미 `anyRequest().permitAll()`(admin만 authenticated).
- **Fix:** SecurityConfig 무변경 — `/api/news`는 기본 공개. NewsControllerIT가 admin 시크릿 없이 200으로 증명.
