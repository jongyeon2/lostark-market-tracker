<objective>
Complete the read API: **server-side downsampling** of large ranges (the same `/prices` auto-aggregates to `avg(min_price)` buckets via PostgreSQL `date_trunc` when raw points exceed N≈500), the **input-validation contract** (from>to / window<=0 → 400, missing item → 404, empty range → 200 empty) wired through the custom `@RestControllerAdvice`, and the **collection health endpoint** `GET /api/health/collection` that surfaces the Phase 2 `collection_run` without leaking secrets.

Purpose: Downsampling protects payload/latency on a 30-day range (design decision 7A — bucket aggregation in the DB, not Java) and is automatic so the client stays dumb (D-08). The validation contract makes 4xx behavior explicit and test-assertable (D-10/D-13). Health turns the Phase 2 run history into an ops surface that proves the pipeline is alive — the operational-maturity showcase (3A) — while the security-critical rule is that it exposes counts/markers only, never the API key.

Output: a native `date_trunc` aggregate query + `DownsampleService`; `PricePoint` DTO + extended `TimelineResponse`; range validation + `InvalidRequestException` extending the 03-01 advice on `PricesController`; `CollectionHealthService` + `HealthController` + `CollectionHealthResponse` + a run finder; Testcontainers ITs for downsample, validation, and health (incl. a no-secret assertion).
</objective>
