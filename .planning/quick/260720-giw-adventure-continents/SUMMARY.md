# Quick Task 260720-giw — 모험의 서 대륙별 분류

모험의 서는 대륙마다 달성도를 채우는 수집품 묶음인데 화면은 이름 검색만 지원해서 "루테란 서부를
채우려면 뭐가 얼마인지"를 볼 수 없었다. 좌측에 대륙 카테고리를 붙이고, 그러려면 서빙 계약을 바꿔야
했다. 이 프로젝트에서 **백엔드를 건드린 첫 UI 작업**이다.

## 데이터 — API가 안 주는 분류를 어떻게 신뢰 가능하게 만들었나

`/markets/options` 실측: 카테고리 `100000 모험의 서`는 **Subs가 빈 배열**, 대륙 필터 파라미터 없음,
아이템 이름에도 대륙 표시 없음. 웹 조사도 전부 실패했다 — 공식 게임가이드는 대륙 이름조차 나열하지
않고, 공식 공략글·나무위키(403)·인벤·INTY 어디에도 "대륙별 거래 가능 수집품 목록"이 없다.

→ 사용자가 **인게임 모험의 서를 직접 열어 노션에 정리**했고, 그것이 유일한 출처다.

🔑 그대로 믿지 않고 거래소 전량(14페이지)과 대조했다:

- 20대륙 × 7 = 140 == 거래소 `TotalCount` 140, 중복 0, 누락 0
- 136개는 문자열까지 동일
- 4개만 표기 차이였고 남은 미매칭 4개와 **1:1로 대응**(일대일이라 다른 해석의 여지가 없다):
  루페온 **시**상→**신**상 / 태양 소금→태양소금 / 사피라 연구 일지→연구일지 / 엘조**원**→엘조**윈**

매칭 키가 아이템 이름이라 거래소 표기를 정본으로 넣었다. `tomes.ts` 작성 후 **재대조까지 통과**
(`tomes.ts에만: []`, `API에만: []`).

## 무엇을 바꿨나

### 백엔드 — 페이지 패스스루 → 전량 캐시

한 대륙의 7개가 14페이지에 흩어져 있어 페이지 단위 계약으로는 만들 수 없다. 이름으로 7번 검색하는
건 7콜 + 부분일치 오염이라 더 나쁘다.

`MarketSearchService.getAdventureAll()`: page 1부터 `totalCount`에 도달할 때까지 걸어 Redis에 통째로
캐시(TTL 10분). `/api/market/adventure`는 파라미터 없이 전량 반환. `search()`는 **무변경**(아바타가 쓴다).

부수 효과가 오히려 좋다 — 옛 계약은 **페이지를 넘길 때마다 1콜**이었는데 이제 **10분에 14콜로 상한이
고정**된다. 페이징도 사라졌다(대륙당 7개).

### 프론트 — 대륙 네비 + 로컬 연산

`tomes.ts`(20대륙 × 7, 거래소 표기) 신설. `AdventurePage`는 좌측 카드에 지도 글리프 + `대륙` 헤더 +
`전체`(140) + 20대륙 leaf(각 개수). 검색·정렬·대륙 필터가 **전부 140행 위 로컬 연산**이라 대륙을
아무리 눌러도 네트워크 요청이 0이다.

### 등급색 (사용자 추가 요청)

`--grade-*` 토큰 5종 신설 + `grades.ts`. 등급 배지에만 색을 넣는다.

### 페이지 제목·부제 제거

아바타·모험의 서의 `<h1>`과 설명 문구 삭제. 상단 네비가 활성 표시로 이미 현재 화면을 말하고,
"시세를 확인하세요"는 시세 보러 온 사람에게 정보가 0이다.

## 핵심 결정 · 근거

- **대륙 매핑은 프론트에.** `categories.ts`(물품)·`classes.ts`(직업군)와 같은 성격이다 — API가 주지
  않는 정적 도메인 분류표이고 소비자가 그 화면뿐이다. 서버는 "140개를 준다"까지만 안다.
- **표에 없는 아이템은 버리지 않고 `미분류` leaf로.** 대륙이 추가되는 날 그 7개가 조용히 사라지는 게
  최악이다. `미분류`가 보이는 것 자체가 "표를 갱신하라"는 신호다(`classes.ts`의 `기타`와 같은 규율).
- **정렬 시 가격 null은 방향 무관 항상 뒤로.** 0으로 치면 낮은가격순에서 "제일 싼 물건"으로 맨 위에
  올라온다 — 값이 없다는 사실을 0원이라고 지어내는 것이다.
- **버킷이 중간에 마르면 실패시킨다.** 14콜은 한 번에 많이 요구하는 양이고 이 버킷은 수집기와
  공유한다(D-03). Core Value가 온디맨드 검색보다 우선이라는 기존 규율 그대로.
- **등급색은 "신규 색 0" 원칙을 뒤집는다.** 로아 유저는 초록/파랑/보라/주황을 등급으로 즉시 읽는데
  흑백 배지로 통일하는 건 유저가 이미 아는 신호를 버리는 쪽이었다. 단 **게임 색을 그대로 쓰지
  않는다** — 게임은 검은 배경, 이 앱은 흰 카드다. 일반은 게임에서 흰색이라 안 보여 중립 회색으로
  대체(유일하게 색상을 바꾼 등급), 나머지는 같은 계열을 어둡게 낮췄다.
- **색은 배지에만.** 게임처럼 이름까지 칠했더니 행마다 본문색이 달라져 목록이 산만했다(라이브 QA).

## 별건 — 무관한 테스트가 오늘 터졌다

`NewsControllerIT`의 픽스처 이벤트가 `endDate = 2026-07-20T06:00:00`으로 하드코딩돼 있었고, 오늘
06:00 KST를 넘긴 시점부터 `isOngoingAt(nowKst)`이 걸러내 `events: []`가 됐다(내가 수정한 news 파일은
0개). 날짜를 미루는 건 타이머를 다시 감는 것이라 **실행 시각 기준 상대 시각**(`now(KST) ±1일`)으로
바꿨다. 나머지 하드코딩 날짜는 전부 `Clock.fixed`·명시적 `NOW`와 함께 쓰여 안전한 것을 확인했다.
