<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin form input → adminRequest → `/api/admin/events` | User-entered event fields cross to the backend behind the secret gate; the backend `@Valid` is the authority |
| KST wall-clock input → UTC storage | A conversion bug would persist wrong instants, corrupting event-impact correlation downstream |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1503-01 | Tampering (wrong instant stored → bad correlation data) | kstDatetime.ts | mitigate | `kstLocalToUtcIso` is the single conversion point (subtract +9h, emit `…Z`); a round-trip acceptance (`utcIsoToKstLocal∘kstLocalToUtcIso`) guards the off-by-9h regression. The backend `occurredAt` remains a UTC `OffsetDateTime` — the frontend never sends a naive local time. |
| T-1503-02 | Elevation of Privilege (mass-assign id/timestamps) | AdminEventRequest | mitigate | The client sends only `{eventType,title,occurredAt,description}`; the backend binds `GameEventRequest` (not the entity), so id/createdAt/updatedAt cannot be set from the body — the frontend cannot forge them either. |
| T-1503-03 | Denial (accidental irreversible delete) | delete flow | mitigate | Delete requires the D-09 inline 2-step confirm ('…되돌릴 수 없습니다.') before the request fires — a single misclick cannot destroy an event. |
| T-1503-04 | Information Disclosure (schema drift silently rendered) | gameEventResponseSchema | mitigate | Responses are `.parse`d at the boundary; a backend shape change fails loudly into `AsyncBoundary`'s ErrorState rather than rendering a malformed row (Phase 7 D-06 extended to writes). |
| T-1503-05 | Spoofing (stale secret write) | adminRequest 401 | mitigate | A 401 on any event mutation triggers the 15-02 global auto-logout (D-03); the write does not silently no-op under an expired secret. |
</threat_model>
