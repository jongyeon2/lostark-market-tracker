# Quick 260630-h16: 품목 타임라인 일별 평균 최저가 집계

## 문제

품목 타임라인 차트가 수집 주기(10분) 그대로의 점을 표기한다. 백엔드 `DownsampleService`는
윈도우 내 원본 스냅샷이 500개 이하면 원본을, 초과하면 시간/일 버킷(`avg(min_price)`)을 내려준다.
현재 dev 실수집이 오늘부터라 500개 미만 → 원본 10분 점이 그대로 노출됨. 사용자 요청:
**타임라인은 항상 하루 단위(일별 평균 최저가)로 표기**.

## 결정 (AskUserQuestion 확정)

- 하루 대표값 = **일별 평균 최저가**(그날 수집된 min_price 스냅샷들의 평균). 기존 백엔드 버킷 집계
  `avg(min_price)`·'버킷 평균' 배지·'N개 평균' 툴팁과 의미 일치 → 가장 일관적.
- 일 경계 = **KST 자정**(로아=한국 게임, RangeControls의 KST 경계 규칙과 동일).
- 7/30/90일 프리셋·커스텀 범위 모두 동일하게 일 단위 적용.

## 접근: 프론트엔드 전용 집계 (백엔드 무변경)

백엔드 read 경로(`DownsampleService`/repository 쿼리)는 D-07/08/09 계약·IT 테스트·불변 백엔드
8파일 보호 대상 → 건드리지 않는다. 반환된 `snapshots`를 프론트에서 KST 일별로 재집계한다.
원본(10분, sampleCount=null)·이미 버킷된 입력(sampleCount=N) 모두 가중평균으로 일관 처리.

## 수정

**Task 1 — 신규 `frontend/src/features/timeline/dailyBuckets.ts`**
- `aggregateDailyAverage(snapshots: PricePoint[]): PricePoint[]`
- KST 달력일(`Intl.DateTimeFormat('en-CA', { timeZone: 'Asia/Seoul' })`)로 그룹화.
- 각 일: 가중평균 `sum(minPrice * w) / sum(w)`, `w = sampleCount ?? 1`, 정수 반올림(골드).
  `sampleCount` = `sum(w)`(그날 표본 수) → 툴팁 'N개 평균'에 사용.
- `collectedAt` = 그 KST 일의 자정을 UTC instant로(`\`${date}T00:00:00+09:00\`` → toISOString),
  off-by-9h 규율 준수(차트 x축 위치·툴팁 라벨 정합).
- 일 오름차순 반환. 빈 입력 → 빈 배열(empty 상태 로직 그대로 유효).

**Task 2 — `frontend/src/features/timeline/TimelinePage.tsx` (ChartArea)**
- `aggregateDailyAverage(snapshots)`로 일별 변환 후 차트/배지에 전달.
- `downsampled={true}` · `bucketWidth="day"` 고정 → '버킷 평균 · 1일' 배지 + 'N개 평균' 툴팁 재사용.
- 빈 상태 판정은 원본 `snapshots.length === 0` 유지(원본 비면 일별도 빔, 동치).
- events(마커)는 집계하지 않음(원래 instant 유지).

**Task 3 — `frontend/src/features/timeline/PriceTimelineChart.tsx` (dot 로직)**
- 현재 `dot={downsampled ? false : rows.length > 60 ? false : { r: 2.5 }}`.
- 일별 집계는 항상 downsampled=true → 기존 규칙이면 점이 안 보임. 특히 현재 dev 데이터는
  오늘치뿐이라 일별 **1점** → 선이 안 그려져 빈 차트처럼 보임.
- → 밀도 기준으로 변경: `dot={rows.length > 60 ? false : { r: 2.5 }}`. ≤60점이면 downsampled여도
  점 표시(희소 일별·단일점 가시화). 배지가 '버킷 평균' 신호를 계속 담으므로 D-08 정직성 유지.
