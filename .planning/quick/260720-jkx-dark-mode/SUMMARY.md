# Quick Task 260720-jkx — 다크모드

`index.css`가 "Light single theme only (dark mode is FE-V2-03)"로 미뤄뒀던 항목. 프로젝트의 마지막
기능. 프론트만, 백엔드 0줄.

## 왜 쌌나

색을 전부 CSS 변수로 소비하는 구조라 대부분이 `.dark` 블록 하나로 따라왔다. 착수 전 하드코딩 색을
전수 조사했더니 **5곳뿐**이었고, 작업 후 재검사에서 **잔존 0건**이 됐다.

## 무엇을 바꿨나

- **`@custom-variant dark`** — Tailwind v4의 `dark:`는 기본이 `prefers-color-scheme` 미디어쿼리라
  수동 토글이 안 먹는다. `<html class="dark">`를 보도록 전환.
- **`.dark` 토큰 블록** — shadcn 표준 slate 계열(사용자 결정). 면 관계를 라이트와 동일하게 유지:
  라이트가 bg=slate-50 / card=흰색으로 **카드가 배경보다 밝으므로**, 다크도 bg=slate-950 /
  card=slate-900. 뒤집으면 같은 컴포넌트가 테마마다 다른 깊이로 읽힌다.
- **FOUC 차단** — `index.html` `<head>`의 인라인 스크립트가 첫 페인트 전에 테마를 확정한다. React
  안에서 하면 번들을 받아 마운트할 때까지 라이트가 먼저 그려져 다크 사용자에게 흰 화면이 번쩍한다.
- **`ThemeToggle`** — 해/달 버튼 하나(2단계). 첫 방문은 OS 설정, 한 번 누르면 localStorage에 기억.
  수동 선택 전에는 OS 변경을 실시간 추종하고, **선택한 뒤에는 OS가 덮지 않는다**.
- **하드코딩 색 5곳 → 토큰**: 차트(grid·tick·시리즈 2색), `impactFormat`, `eventMarkers` 8색,
  `--grade-*` 다크 변형, 클래스 아이콘 `dark:invert`.
- **`color-scheme`** — 라이브 QA에서 발견. 네이티브 위젯(스크롤바·date 달력)은 CSS 변수를 안 보고
  브라우저가 `color-scheme`으로 칠한다. 안 주면 다크 화면에 밝은 회색 스크롤바가 남는다.

## 🔑 함정 — `impactFormat.ts`를 기존 토큰으로 "정리"할 뻔했다

세 hex를 `--up`/`--down`으로 바꾸는 게 자연스러워 보였지만 **정반대였다**. 주석에 적혀 있듯 이 화면은
국내 거래소/MTS 관례(**상승=빨강 · 하락=파랑**)를 따르고, `--up`(green)/`--down`(red)과 **의미 축이
반대**다. 그대로 바꿨으면 라이트 화면의 색이 뒤집혔을 것이다.

→ 전용 토큰 `--change-up/down/flat`을 새로 만들고 라이트 값은 **기존 hex 그대로** 옮겼다. 그 구분의
이유도 원래 주석에서 토큰 주석으로 함께 옮겼다.

## 핵심 결정 · 근거

- **클래스 아이콘은 `dark:invert`.** 공식 SVG가 `fill="#222222"` **단색**이라 반전이 정확히 `#DDDDDD`를
  만든다. `mask-image`로 currentColor를 상속시키거나 흰색 세트를 하나 더 번들하는 것보다 싸고,
  `<img>`를 유지하므로 `onError` 폴백도 살아있다. (다색 아이콘이었다면 색상까지 뒤집혀 못 썼다.)
- **`eventMarkers.ts`는 소비처 수정 0.** hex를 `var(--event-*)`로 바꿨는데, 세 소비처(차트 SVG
  `stroke`, 배지 inline `style.borderColor/color`, 범례 `style.backgroundColor`)가 전부 CSS 변수를
  그대로 받는다. Recharts도 마찬가지라 차트 색을 토큰으로 옮기는 데 래퍼가 필요 없었다.
- **역할 알약은 다크에서 밝히고 글자를 뒤집었다.** 라이트는 "진한 배경 + 흰 글자"인데 어두운 배경에선
  진한 알약이 묻힌다. 알약이 면으로 보여야 라벨이 읽힌다.
- **등급 `일반`은 다크에서도 게임의 흰색을 안 쓴다.** 본문색과 같아져 "등급 없음"처럼 읽히므로 중립
  회색 유지 — 라이트에서 흰색을 못 쓴 것과 이유는 다르지만 결론은 같다.
- **테마 판정 로직은 한 곳에만.** `ThemeToggle`은 `<html>`의 클래스를 **읽기만** 한다. 초기값을 다시
  계산하면 인라인 스크립트와 규칙이 중복되고, 어긋나는 순간 화면과 버튼 아이콘이 반대가 된다.

## 라이브 QA가 잡은 것

- **네이티브 스크롤바가 밝게 남음** — `color-scheme`을 안 줘서. 계산이나 빌드로는 안 잡히고 실제
  화면을 봐야만 보이는 종류였다. `:root{color-scheme:light}` / `.dark{color-scheme:dark}`로 해결.

## 후속 — 배포 후 CSP 위반 2건 (커밋 72e5816 · 7127536)

푸시 후 사용자가 운영 콘솔에서 폰트 CSP 오류 4건을 발견했다. 조사하다 **같은 유형의 두 번째 건이
이 작업에서 들어간 것**을 함께 찾았다.

| 건 | 원인 | 조치 |
|---|---|---|
| 폰트 4개 차단 (기존 버그) | Vite 기본 `assetsInlineLimit`(4KB)이 작은 폰트 서브셋을 `data:` URI로 인라인 → `font-src 'self'` 위반 | `vite.config.ts`에서 폰트 인라인 금지. data:font 4→0, 폰트 파일 15→19 |
| 테마 스크립트 차단 (**이 작업이 넣은 것**) | FOUC 차단 스크립트를 `index.html` 인라인으로 둠 → `script-src 'self'` 위반 | `public/theme-init.js`로 분리(동일 출처) |

🔑 **왜 못 잡았나**: 둘 다 **로컬에서 재현되지 않는다**. `npm run dev`는 에셋을 인라인하지 않고 CSP
헤더는 운영 Caddy에만 있다. 빌드도 타입 체크도 대비 계산도 통과한다 — 운영 헤더가 있어야만 보인다.

🔑 **재발 방지 방법**: 운영 Caddyfile과 **동일한 CSP 헤더로 `dist/`를 로컬 서빙**해 브라우저로 확인하는
절차를 썼다(임시 정적 서버 + Playwright). `/avatar`·`/dashboard` 콘솔 에러 0, 저장된 다크 설정이
새로고침 후에도 첫 페인트에 적용됨(`html class="dark"`, body `rgb(2,6,23)`)을 실측했다. 앞으로 CSP에
걸릴 만한 변경(인라인 스크립트/스타일, 새 외부 출처, 번들러 설정)을 할 때 이 절차를 쓰면 된다.

두 건 모두 **CSP를 넓히지 않고 정책을 지키는 쪽**으로 고쳤다. `font-src`에 `data:`를 더하거나
`script-src`에 `'unsafe-inline'`을 더하면 한 줄로 끝나지만, 그건 도구 편의를 위해 보안 정책을 깎는
것이다. `index.css`가 "self-host라 font-src 'self' 통과"라고 적어둔 의도가 옳았다.
