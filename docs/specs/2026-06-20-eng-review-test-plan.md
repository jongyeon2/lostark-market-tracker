## Key Interactions to Verify
- 스케줄 틱: 병렬 팬아웃 + allOf().join()로 느린 카테고리가 틱을 막지 않음
- fixedDelay 직렬화: 비동기 await 덕에 틱 중복 실행 없음(분산 락 불필요 검증)
- @Async 태스크 안 새 트랜잭션 + ID 전달 → LazyInitializationException 없이 커밋
- 토큰버킷: 소진/회복, 재시작 후 lazy refill로 토큰 복원
- 429: Retry-After 존중 + 지수 백오프 + 최대 3회 후 스킵-라이트; 401/5xx 별도 경로
- 캐시-어사이드: 2번째 읽기 시 리포지토리 DB 호출 0회(spy); 쓰기 시 최신가 키 무효화

## Edge Cases
- 부분 실패 틱: 스냅샷 미기록 + collection_run에 실패 기록(널 행 금지)
- event-impact: 앞/뒤 윈도우 각 1개 미만 → insufficient_data
- event-impact: 앵커 스냅샷이 staleness 허용치 밖(구멍) → insufficient_data
- 타임라인 경계: from/to 포함·배제 일관성
- UTC 저장/KST 표시: 이벤트가 KST 자정 근처일 때 off-by-9h 없음
- 입력 검증: from>to → 400, window<=0 → 400, 없는 itemId → 404, 빈 범위 → []
- 관리자: 시크릿 없이 401/403, 시크릿 있으면 200

## Critical Paths (E2E, Testcontainers Postgres+Redis)

- 이벤트 등록(관리자, 인증) → 타임라인에 겹쳐 반환 → event-impact 델타 계산
