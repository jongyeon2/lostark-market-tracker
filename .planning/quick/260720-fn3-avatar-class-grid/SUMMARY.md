# Quick Task 260720-fn3 — 아바타 직업 바둑판 + 페이지 배치 재구성

드롭다운 하나를 아이콘 그리드로 바꾸는 작업으로 시작했는데, 라이브 QA를 거치며 아바타 페이지
**전체 배치**를 다시 짜는 것으로 커졌다. 백엔드 0줄.

## 무엇을 바꿨나 (최종 상태)

- **직업 선택 = 아이콘 바둑판.** shadcn `Select` 폐기. 직업군 블록(3열 = 6인 그룹이 정확히 2줄)을
  화면 폭만큼 가로로 배열(`sm:2 → lg:3 → xl:4 → 2xl:5`). 흰 `Card` 한 장으로 감싸 아래 영역과 분리.
  그룹 라벨엔 `border-b` 밑줄로 구분선.
- **공식 클래스 SVG 30개 번들** — `frontend/public/class-icons/`.
- **`classes.ts` 신설** — 직업군 7그룹 + 한글 직업명→아이콘 slug. `groupClasses()`가 API 응답을
  단일 출처로 삼는다.
- **필터를 전부 상단으로.** 좌측 11rem 부위 기둥을 없애고 부위 칩 + 검색 + 정렬을 카드 하나로 통합.
  위→아래가 실제 사용 순서(직업→부위→검색→결과)와 같아졌고, 상단 직업 카드와 좌우 끝이 맞는다.
- **시세 목록 2열** — `MarketResultList`에 `className` 주입구(기본 `space-y-2`). 아바타만
  `grid gap-2 lg:grid-cols-2`, 모험의 서는 기본값 유지.

## 데이터 출처 — 추측 0

공식 API는 **직업 아이콘도 직업군 분류도 주지 않는다**(`/markets/options`의 `Classes`는 한글
문자열 30개뿐, 실측). CDN 경로 추측은 전부 404. 그래서 공식 웹사이트 자산에서 원본을 뽑았다:

- 아이콘 파일명: `2018/obt/assets/css/pc.css` 의 `.icon--*` 배경 이미지 경로
- 직업군↔클래스: `2018/obt/assets/js/pc.js` 의 `{root_ko, root_en, list:[{name_ko, name_en}]}`

추출한 30개가 **라이브 API의 30개와 집합으로 완전히 일치**함을 스크립트로 확인했다(`기타` 그룹
발생 0). 파일명은 규칙적이지 않아 유추하면 404다 — 소울이터는 `souleater`(언더바 없음), 차원술사는
`dimension_master`(있음), 가디언나이트의 파일은 `dragon_knight.svg`.

공식 데이터는 성별까지 쪼갠 11 root지만 화면에선 성별만 병합해 7그룹으로 뒀다. "전사(남)" 4개와
"전사(여)" 2개를 따로 세우면 3열 2줄이 깨지고, 유저가 직업을 찾는 단위는 성별이 아니다.

## 핵심 결정 · 근거

- **아이콘은 핫링크가 아니라 번들**(사용자 결정). 아이템 아이콘은 API가 준 `iconUrl`이라 핫링크가
  정당하지만, 이 URL들은 사이트 내부 자산이라 예고 없이 옮겨질 수 있다.
- **매핑에 없는 신규 직업은 드롭하지 않고 `기타` 그룹으로.** 신규 직업 출시일에 그 직업만 조용히
  선택 불가가 되는 게 최악이다. 아이콘이 없어도 이름으로는 고를 수 있다.
- **폭을 줄이는 대신 폭을 쓴다.** "직업 박스가 너무 넓다"는 피드백에 처음엔 `max-w-6xl` 상한을
  제안했지만, 원인은 카드가 아니라 **내용이 폭을 못 채우는 것**이었다(타일 160px에 아이콘 24px).
  열 수를 올리고 시세를 2열로 깔아 폭을 활용하는 쪽으로 뒤집었다(사용자 결정).
- **부위 sticky를 포기했다.** 상단 통합의 대가. 한 페이지가 10개(2열이면 5줄)라 스크롤 중 부위를
  바꿀 일이 드물다고 봤다 — 불편하면 칩 행만 sticky로 되돌릴 수 있다.
- **부위 칩은 `flex-wrap`, 가로 스크롤 아님.** 스크롤은 오른쪽에 뭐가 더 있는지 보여주지 않는다.

## 검증

- `npm run build`(`tsc -b && vite build`) 통과.
- SVG 30개: 전부 HTTP 200 + `<svg` 시작(404 HTML 혼입 0), md5 중복 0건, slug↔파일명 30↔30 일치.
- `classes.ts` 직업명 30개 == 라이브 API 30개(집합 동일).
- 사용자 라이브 QA: "확실히 보기 편해졌다" → "매우 만족스럽다".
