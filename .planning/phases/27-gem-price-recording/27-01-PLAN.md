# Phase 27-01 — 보석 시세 기록 시작 (GEM-03)

## 왜 이 phase가 v1.7의 제약을 뒤집나

GEM-02는 **"보석은 시계열 미기록"**을 불변 제약으로 명시했고 `GemService`의 클래스 주석도
"a 5분 poller would spend ~1.2 calls/min forever"라고 폴러를 거부한 근거를 적어놨다.
**그 판단은 5분 주기 기준으로는 여전히 옳다.** 이 계획이 바꾸는 건 주기이지 원칙이 아니다:

| | 하루 콜/행 | `price_snapshot` 대비 | 분당 콜 (한도 100) |
|---|---|---|---|
| 거래소 수집 (49품목 × 10분) | ~7,056 | 100% | ~4.9 |
| 보석 5분 폴러 (GEM-02가 거부한 것) | 1,728 | 24% | **1.2** |
| **보석 1시간 폴러 (이 계획)** | **144** | **2%** | **0.1** |

v1.7이 막으려던 것은 시계열 기록 자체가 아니라 **수집 예산을 잠식하는 빈도의 기록**이었다.
1시간 주기는 그 선 아래이므로 제약을 **근거와 함께** 해제한다. `GemService`의 해당 주석도
"폴러는 없다"에서 "**서빙**은 폴러를 쓰지 않는다"로 정정한다 — 아래 §서빙과 기록의 분리 참조.

## 근거 (전부 Phase 24 실측 — 새로 추측하는 값 없음)

- 현재가 = `min(BuyPrice)` = `Sort=BUY_PRICE`+`SortCondition=ASC`+`PageNo=1` → `Items[0].AuctionInfo.BuyPrice`
- **`Id` 없음** → `tracked_item` FK 재사용 불가. 보석의 키는 **(계열, 레벨)**이다.
- **레이트리밋 버킷을 거래소 수집과 공유** → 기록도 같은 버킷에서 예산을 얻어야 한다.
- `BuyPrice` **null 가능**(입찰 전용 매물) → "즉시구매 매물 없음"은 실재하는 답이다.
- **경매장엔 히스토리 엔드포인트가 없고 `Id`가 없어 백필이 불가능하다** → 이 폴러가 켜지는 순간이
  보석 시계열의 시작점이다. 그래서 표보다 폴러가 먼저다.

## 설계 결정

**서빙과 기록을 분리한다.** 폴러가 `gem:latest` 캐시를 덮어쓰면 `/gems` 헤드라인이 최대 1시간 묵은
값이 된다 — 지금은 ≤5분이다. "현재가"라는 이름을 단 화면에 어제 값을 띄우지 않는다. 그래서
**폴러는 DB에만 쓰고 캐시는 건드리지 않는다.** 서빙은 지금 그대로 온디맨드(무방문 0콜) 유지.
둘은 다른 일이고, 합치면 둘 다 나빠진다.

**토큰 버킷 획득을 `GemPriceFetcher` 한 곳으로 모은다.** Phase 26의 실버그는 보석이 공유 버킷을
우회한 것이었다. 서빙과 기록이 각자 `tryAcquire`를 호출하면 **그 실수를 할 자리가 둘로 늘어난다.**
`GemService`에서 `fetchOne`/`fetchAll`/`row`를 `GemPriceFetcher`로 옮기고 서빙·기록이 함께 쓴다.
버킷 규칙의 집은 하나여야 한다.

**답받은 것만 기록한다 — 상태 컬럼 없이.**
- `OK` → 행 + 가격
- `NO_BUYOUT` → 행 + `min_buy_price = NULL` ("물어봤고, 즉시구매 매물이 없었다")
- `RATE_LIMITED` / `FETCH_FAILED` → **행 없음** ("못 물어봤다")

이러면 `NULL`과 **행 부재**가 서로 다른 사실을 정확히 하나씩 말하므로 `status` 컬럼이 필요 없다.
훗날 일별 표가 "그날 매물이 없었다"와 "그 시각 폴러가 죽어 있었다"를 구분할 수 있어야 하는데,
이 구조가 그걸 공짜로 준다. 값을 지어내지 않는 원칙(`insufficient_data`·쿠폰 `startsAt` null)의 연장.

**`recorded_at`(실제 측정 순간) + `hour_slot`(멱등 키)를 분리한다.** 하나로 합쳐 정각 반올림하면
"10:05에 잰 값"이 "10:00에 잰 값"이 되어 **측정 시각을 왜곡**한다(`EventImpactService`가 일평균에
자정 타임스탬프를 지어내길 거부한 것과 같은 규율). `hour_slot`은 오직 `UNIQUE`를 걸어 한 시간에
한 행만 남기기 위한 파생 컬럼이다.

**멱등은 `ON CONFLICT DO NOTHING`(먼저 온 표본이 이긴다).** `item_daily_stats`는 `DO UPDATE`로
제자리 갱신하지만(같은 날의 평균은 나중 값이 더 정확하다) 보석은 다르다 — **각 표본은 그 순간의
사실**이라 나중 값이 더 옳지 않다. 재기동 루프가 기록을 계속 덮어쓰지 않게 하는 효과도 있다.
CI/CD가 `main` push마다 재배포하므로(Phase 19) 부팅이 잦다 — **이 제약이 배포 폭풍을 그대로 흡수한다.**

### Task 1 — V9 마이그레이션 + 엔티티 + 리포지토리

**action:** additive 신규 테이블만. V1–V8 무변경(Flyway 체크섬 유지), `price_snapshot` 무변경.

**files:**

```sql
CREATE TABLE gem_price_snapshot (
    id            BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    series        VARCHAR(20) NOT NULL,
    level         SMALLINT    NOT NULL,
    min_buy_price BIGINT,                  -- NULL = 물어봤고 즉시구매 매물이 없었다
    recorded_at   TIMESTAMPTZ NOT NULL,    -- 실제 측정 순간(반올림 금지)
    hour_slot     TIMESTAMPTZ NOT NULL,    -- recorded_at을 시간으로 절삭 — 멱등 키 전용
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT uq_gem_price_snapshot UNIQUE (series, level, hour_slot)
);
CREATE INDEX ix_gem_price_snapshot_gem_time ON gem_price_snapshot (series, level, recorded_at);
```

- `tracked_item` FK **없음** — 보석은 `Id`가 없고 워치리스트 품목이 아니다(24 §H5).
- 리포지토리는 `ItemDailyStatRepository` 선례대로 **네이티브 upsert**(`ON CONFLICT DO NOTHING`).
- 엔티티는 `ddl-auto=validate` 검증용 + 읽기용. `@PrePersist`는 `ItemDailyStat` 패턴.

**verify:** `./gradlew build` 그린(Testcontainers가 V9까지 마이그레이트 + `validate` 통과).
