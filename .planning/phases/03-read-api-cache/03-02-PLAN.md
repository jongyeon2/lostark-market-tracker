<objective>
Deliver the **timeline read** — `GET /api/items/{id}/prices?from=&to=` returning **two separate arrays** `{snapshots, events}`: the window's price snapshots (ascending) and the `game_event`s whose `occurred_at` falls inside the window — and extract the **4A shared window query** (`WindowQueryService`) that Phase 5 event-impact will reuse. Event overlap is inclusive containment (`from <= occurred_at <= to`); all boundaries are UTC.

Purpose: This is the chart-overlay data contract (design §Worktree B timeline, decision 4A/T6). Extracting the window query now (not inlining it in the controller) is the deliberate DRY/N+1 move — Phase 5 calls the exact same `WindowQueryService` to gather pre/post-event snapshots, so the boundary semantics are defined and tested once here. Snapshots and events stay in distinct arrays so downsampling (03-03) can shrink snapshots without touching events (D-04 orthogonality).

Output: `GameEventRepository` (new) + a read-only window finder on `PriceSnapshotRepository`; `WindowQueryService` (4A) returning `WindowResult`; `TimelineResponse`/`SnapshotPoint`/`EventPoint` DTOs; `PricesController` with `/prices`; Testcontainers ITs proving the two-array shape, inclusive overlap (on-boundary), ascending order, UTC boundaries, 404, and empty-window 200.
</objective>

| T-0302-03 | Information Disclosure | Event/snapshot payload | accept | Timeline returns only public market prices + admin-curated event metadata (type/title/occurred_at); no secrets or PII. |
