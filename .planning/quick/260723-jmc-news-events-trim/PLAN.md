# Quick Task 260723-jmc — 대시보드 첫 화면: 이벤트 배너 접기

## 왜 — 페이지 길이를 시세가 아니라 배너가 결정하고 있다

사용자 피드백("첫 화면에 읽을 게 많아 가시성이 떨어진다")을 배포 사이트에서 실측했다(1440×900, 2026-07-23).

| 측정 | 값 |
|---|---|
| 전체 페이지 높이 | **약 1,520px** |
| 중앙(물품 목록) 끝 | 약 770px |
| 좌측(카테고리+공지) 끝 | 약 900px |
| 우측(쿠폰+이벤트) 끝 | **약 1,425px** |

**하단 약 650px는 좌·중앙이 빈 채로 오른쪽 배너만 이어진다.** 이벤트 카드 1장이 약 194px(썸네일 16:9 + 제목·기간)이고 6장이 쌓이므로 우측만 1,163px를 쓴다.

더 중요한 건 **시각 위계가 뒤집혔다는 것**이다. 화면의 유일한 컬러 이미지 6장이 전부 우측 배너다. 정작 핵심인 중앙 시세 목록은 흰 배경 위 무채색 텍스트라, 눈이 제일 먼저 가는 곳이 제일 안 중요한 곳이 된다.

🔑 **총 정보량이 문제가 아니다** — 공지 6행·물품 8행은 그대로 둬도 조용하다. 문제는 컬러 면적과 페이지 높이를 한 위젯이 독점하는 것이다. 그래서 이 작업은 **이벤트만** 건드린다.

## 왜 별도 페이지로 빼지 않는가 (사용자 결정 2026-07-23)

- 쿠폰은 이 화면에서 **유일하게 누를 수 있는 요소**(복사 버튼)다. 빼면 첫 화면이 순수 조회 전용이 된다.
- 분리한 페이지는 결국 외부 링크 모음이라 재방문 이유가 약하다.
- 원인(높이·컬러 면적)이 분리 없이 해결된다. 그래도 시끄러우면 그때 분리를 검토한다.

## 왜 외부 링크가 아니라 인플레이스 토글인가

공식 진행중 이벤트 목록(`lostark.game.onstove.com/News/Event/Now`, 실측 200)으로 보내는 안도 있었지만 택하지 않았다. **더보기가 사이트를 떠나는 문이 되면 안 된다** — 각 카드는 이미 개별 공식 링크를 갖고 있고, 목록을 더 보려다 이탈시킬 이유가 없다. 접힌 상태가 기본이면 높이 문제는 이미 해결되고, 펼친 상태는 **오늘과 정확히 같은 화면**이라 잃는 게 없다.

## 사전 확인 (실측 2026-07-23)

| 확인 | 결과 |
|---|---|
| `GET /api/news` 응답 | events **6**, notices **6** |
| `MAX_ROWS = 6` 사용처 | 쿠폰·공지·이벤트 **3곳이 공유** — 이벤트만 떼야 한다 |
| 이벤트 카드 실측 높이 | 약 194px/장 (썸네일 16:9 + 제목 2줄 clamp + 기간) |

## 작업

**단일 파일: `frontend/src/features/dashboard/NewsPanel.tsx`**

1. `MAX_ROWS = 6`은 **쿠폰·공지 전용으로 남긴다**(두 위젯의 현재 동작 유지).
2. `COLLAPSED_EVENT_ROWS = 3` 신설. `EventSection`이 기본 3장만 렌더한다.
3. `EventSection`에 `useState` 펼침 토글 + 목록 아래 버튼 한 개.
   - 접힘: `이벤트 N개 더보기` / 펼침: `접기`
   - 이벤트가 3개 이하면 버튼을 **렌더하지 않는다**(누를 게 없는 버튼 금지).
4. 펼친 상태 = 오늘과 동일한 6장. 상한을 늘리지 않는다.

## 기대 결과

접힌 기본 상태에서 우측 컬럼이 약 582px(3×194) 줄어 **페이지 1,520px → 약 930px**. 좌측(900px)·중앙(770px) 끝과 정렬되어 하단 빈 구간이 사라진다.

## 하지 않는 것

- **쿠폰·공지는 손대지 않는다.** 6행 유지 — 텍스트라 시각 무게가 낮고, 원인이 아니다.
- **썸네일 크기·레이아웃 변경 없음.** 이번엔 개수만 건드려 효과를 격리 측정한다.
- **백엔드 무변경.** `NewsService`의 6개 응답은 그대로 쓴다(펼침이 오늘 동작과 같으려면 그래야 한다).
- 모바일(<lg) 별도 분기 없음 — 같은 컴포넌트라 접힘이 그대로 적용되고, 세로 화면에서 더 이득이다.
