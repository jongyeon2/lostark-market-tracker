<objective>
Assemble the Dashboard: rewrite **`DashboardPage`** to compose the full-width `HealthCard` (08-02) on top and, below it, a responsive **item-card grid** from `useItems()` (DASH-03) — replacing the Phase-7 temporary `<li>` list and realizing the D-01 hierarchy 'health → 무엇을 추적 → 지금 얼마'. Build **`ItemCard`** so each active item is one unified card (D-01): `displayName` + `category` on top, and a latest-price area fed by its **own** `useLatestPrice(item.id)` hook inside its **own** `<AsyncBoundary>` (D-03 per-card fan-out) — minPrice + `collectedAt` (formatKst) on success, a card-level '최신가 아직 없음' on 404/uncollected, a skeleton while pending (DASH-04). Items render in the backend's order with no re-sort (D-02); the grid shows the Phase-7 `EmptyState` when there are zero items.

The engineering signal is **honest per-widget independence**: each card owns its own request and its own loading/error/empty, so a single item's latest failure never hides its neighbors or the health card (D-07/D-08) — and the N-requests cost of card-level fan-out (no batch endpoint exists; that's a backend change → Deferred) is taken deliberately as the simplest correct design for the seed watchlist, a trade-off worth narrating in the portfolio (D-04).

Output: `src/features/dashboard/ItemCard.tsx` + the rewritten `src/features/dashboard/DashboardPage.tsx`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `/api/items` + `/api/items/{id}/latest` responses → rendered cards | displayName/category/minPrice/collectedAt from the API are rendered into item cards |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-0803-01 | Tampering / XSS (rendering API strings) | ItemCard / DashboardPage | mitigate | displayName/category and numeric minPrice are rendered as JSX text children (React-escaped); no `dangerouslySetInnerHTML`. Both responses are zod-validated upstream (07-02 trackedItemsSchema/latestPriceSchema) before render, so a crafted name/category cannot inject markup. |
| T-0803-02 | Denial of Service / UX crash (one item failure blanks screen) | ItemCard AsyncBoundary | mitigate | Each ItemCard owns its `useLatestPrice` request + AsyncBoundary (D-03/D-07): a 404/uncollected/down renders an inline '최신가 아직 없음' in just that card; the grid- and health-level boundaries are separate, so one item's failure never blanks the grid or the health card (완료조건 #5). |
| T-0803-03 | Resource Exhaustion (N latest requests) | DashboardPage fan-out | accept | N active items → N `/api/items/{id}/latest` requests is a deliberate, documented trade-off (D-04): the seed watchlist is small, React Query dedupes/caches per id, and a batch endpoint is a backend change (out of scope → Deferred/v2). No client-side amplification beyond one request per visible card. |
| T-0803-04 | Elevation of Privilege (write/admin surface) | DashboardPage | accept | The screen is read-only: no admin/write route, form, or `X-Admin-Secret` (FE-V2-01 out of scope); the only CTAs are the read-only '다시 불러오기' refetches inside the boundaries. No privileged surface exists. |

</threat_model>
