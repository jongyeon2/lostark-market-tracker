# Quick 260630-h16: 품목 타임라인 일별 평균 최저가 집계 Summary

**품목 타임라인 차트를 수집 주기(10분) 원본 점 대신 항상 하루 단위(일별 평균 최저가)로
집계해 표기. 프론트엔드 전용 집계 — 백엔드 read 경로·zod 스키마·계약 무변경. playwright
실측으로 일별 1점/일·'버킷 평균 · 1일' 배지·단일점 dot 가시화·런타임 에러 0 검증.**

## 배경 (근본 원인)

백엔드 `DownsampleService`는 윈도우 내 원본 스냅샷이 ≤500이면 원본(10분 점), >500이면
시간/일 버킷(`avg(min_price)`)을 내려준다. 현재 dev 실수집이 오늘(2026-06-30 01:49Z~)
부터라 7점 < 500 → 원본 10분 점이 그대로 노출됨(정상 동작). 사용자 요청은 데이터 양과
무관하게 **타임라인을 항상 하루 단위**로 표기.

## 결정 (AskUserQuestion 확정)

하루 대표값 = **일별 평균 최저가**(그날 min_price 스냅샷들의 평균). 기존 백엔드 버킷
`avg(min_price)`·'버킷 평균' 배지·'N개 평균' 툴팁과 의미가 정확히 일치 → 가장 일관적.
일 경계 = KST 자정. 7/30/90일 프리셋·커스텀 범위 모두 동일 적용.

## 접근: 프론트엔드 전용 집계 (백엔드 무변경)

백엔드 read 경로(`DownsampleService`/repository)는 D-07/08/09 계약·IT 테스트·불변 백엔드
8파일 보호 대상 → 미변경. 반환된 `snapshots`를 프론트에서 KST 일별로 재집계. 원본(10분,
sampleCount=null)·이미 버킷된 입력(sampleCount=N) 모두 가중평균으로 일관 처리.

## 수정

- **신규 `dailyBuckets.ts`** — `aggregateDailyAverage(snapshots)`: KST 달력일
  (`Intl en-CA, Asia/Seoul`)로 그룹화, 가중평균 `sum(min*w)/sum(w)`(`w = sampleCount ?? 1`,
  정수 반올림), `sampleCount = sum(w)`(그날 표본 수, 'N개 평균'용). `collectedAt` = 그 KST
  일의 자정을 UTC instant로(off-by-9h 규율). 일 오름차순. 빈 입력 → 빈 배열.
- **`TimelinePage.tsx`(ChartArea)** — `aggregateDailyAverage` 적용, `downsampled`·
  `bucketWidth="day"` 고정으로 배지/툴팁 재사용. 빈 상태 판정은 원본 `snapshots.length===0`
  유지. events(마커) 무집계.
- **`PriceTimelineChart.tsx`** — dot 로직 `downsampled ? false : rows>60 ? false : {r}` →
  `rows>60 ? false : {r:2.5}`(밀도 기준). 일별은 항상 downsampled=true라 기존 규칙이면
  점이 안 보이고, 현재 dev 데이터는 일별 1점 → 단일 점은 dot 없으면 렌더 안 됨. 배지가
  버킷 신호를 계속 담아 D-08 정직성 유지.
