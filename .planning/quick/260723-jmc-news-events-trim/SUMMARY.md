# Quick Task 260723-jmc — 대시보드 첫 화면: 이벤트 배너 접기

## 무엇을 바꿨나

`NewsPanel.tsx` 한 파일. 진행중 이벤트가 **기본 3장**만 보이고, 목록 아래 `이벤트 N개 더보기` 버튼으로 나머지를 펼친다. 쿠폰·공지는 손대지 않았다.

**대시보드 콘텐츠 높이 1,515px → 961px (−37%).** 배포본에서는 스크롤이 필요했지만 접힌 상태에서는 첫 화면에 다 들어온다.

## 핵심 결정 · 근거

- **`MAX_ROWS = 6`을 쿠폰·공지 전용으로 남기고 `COLLAPSED_EVENT_ROWS = 3`을 새로 뒀다.** 한 상수를 셋이 공유하던 동안에는 이벤트만 줄일 수가 없었다. 쿠폰·공지는 원인이 아니므로(텍스트라 시각 무게가 낮다) 동작을 그대로 유지하는 게 맞다.
- **외부 링크가 아니라 인플레이스 토글.** 공식 진행중 이벤트 목록(`lostark.game.onstove.com/News/Event/Now`, 실측 200)으로 보낼 수도 있었지만, 각 카드가 이미 개별 공식 링크를 갖고 있어서 **목록을 더 보려다 사이트를 떠나게 만들 이유가 없다.**
- **펼침 상한은 `MAX_ROWS` 그대로.** 펼친 화면 = 이 작업 이전과 동일(실측 1,554px ≈ 배포본 1,515px). 접는 것이지 버리는 게 아니다.
- **펼침 상태는 로컬 `useState`.** URL에도 서버에도 남기지 않는다 — 대시보드 카테고리 선택과 같은 판단(A4 YAGNI).
- **이벤트가 3개 이하면 버튼을 렌더하지 않는다.** 누를 게 없는 버튼은 있으나 마나가 아니라 거짓말이다.
- **버튼은 `variant="ghost"`.** 이 작업의 목적이 우측 시각 무게를 덜어내는 것인데, 배너 아래에 또 하나의 진한 블록을 놓으면 자기모순이다.

## 검증 (실측 2026-07-23)

로컬 검증은 `VITE_API_TARGET=https://loaket.kr npm run dev`로 **운영 API의 실제 데이터**를 프록시해 수행했다(추적 파일 수정 0 — vite.config가 이미 제공하는 오버라이드).

## 알려진 대가

- 진행중 이벤트를 전부 보려면 클릭 1회가 필요해졌다. **의도된 교환**이다 — 배너는 이 사이트의 핵심이 아니고, 핵심(시세)이 첫 화면을 차지하는 편이 낫다.
- 카테고리를 바꿔도 펼침 상태는 유지된다(다른 컴포넌트라 서로 영향 없음). 문제로 보이면 그때 다룬다.

## 범위 밖

- **쿠폰·공지** — 6행 유지. 텍스트라 시각 무게가 낮고 페이지 높이를 지배하지 않는다.
- **썸네일 크기·레이아웃** — 이번엔 개수만 건드려 효과를 격리 측정했다. 여전히 무겁다면 다음 후보다.
- **우측 컬럼 sticky + 높이 상한** — 접기만으로 높이가 해결돼 불필요해졌다.
- **백엔드** — `NewsService`의 6개 응답 그대로. 펼침이 오늘 동작과 같으려면 그래야 한다.
