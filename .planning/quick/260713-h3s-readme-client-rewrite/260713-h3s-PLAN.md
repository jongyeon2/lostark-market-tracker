## Task 1 — README.md 리라이트 + 라이브 스크린샷 교체

**Files:** `README.md`, `frontend/docs/screenshots/{dashboard,item-timeline,event-impact}.png`

**Action:**
1. 스크린샷 3장을 **배포 사이트 실제 캡처**(1440px)로 교체 — 완료(dashboard·timeline은 실데이터,
   impact은 라이브 빈 상태=정직한 insufficient_data 서사, 캡션으로 강점화).
2. 상단(가시 영역, 쉬운 말): 제목+배지 → 한 줄 소개 + **🔗 라이브 링크** → 타임라인 히어로 이미지
   → "이런 서비스예요"(무엇/왜, 2~3문단) → "직접 보기"(라이브 URL·3화면·타임라인 딥링크·스크린샷)
   → 기술 스택(중복 3곳→1곳) → "어떻게 배포했나"(Oracle VM·Compose·Caddy 자동 HTTPS, 몇 줄)
   → "어떻게 만들었나(AI 협업)"(다듬은 짧은 버전).
3. 하단 `<details>` 접기: 로컬 실행(seed/dev 압축) · 아키텍처 mermaid · 설계 결정(핵심만) ·
   API 예시(4개→대표 1개 event-impact + 표) · 시각 enrichment(4소절→1문단) · 프로젝트 구조 ·
   스코프/한계 · 문서 링크.
4. 개발자 정보로 마무리.

**Verify:** 상단이 링크·이미지 클릭만으로 "무엇/왜/어디서 보나/스택/배포"가 파악되고, 깊이는 접힘 안에
보존. 라이브 URL·딥링크 정상, 이미지 경로 유효. 목표 ≈130~150줄.

**Done:** 첫 독자는 30초에 이해, 면접관은 접기 펼쳐 깊이 확인. 코드 0줄(문서+이미지).
