# v1.5 설계 — 시세 범위 확장(스펙업 재료) + 대시보드 UX + 이벤트 카테고리

**Date:** 2026-07-14
**Status:** 설계 확정(brainstorming) — 사용자 승인 완료. 실행은 GSD(마일스톤 v1.5)로.
**참조:** maplanet.net(레이아웃 참고), 로스트아크 Open API(MARKETS/AUCTIONS), 프로젝트 스파이크 `12-SPIKE-FINDINGS`·`17.4-SPIKE-FINDINGS`.

## 배경 · 목표

v1.4(CI/CD 자동화)까지 완료된 시세 파이프라인 위에, **사용자가 실제로 쓰는 "스펙업 재료" 중심으로 시세 커버리지를 넓히고**, 대시보드를 maplanet식 3열(좌 카테고리 / 중앙 물품 / 우 소식)로 재구성하며, 이벤트 상관 분석의 표현력을 이벤트 카테고리 확장으로 높인다.

세 갈래(독립적으로 가치 있음):
- **A. 대시보드 3열 카테고리 레이아웃** (프론트 UX)
- **B. 이벤트 카테고리 +3** (상관 분석 표현력)
- **C. 시세 범위 확장 — 스펙업 재료** (커버리지)

## Core Value 가드 (불변)

**레이트리밋이 걸린 외부 마켓 API에서 시세를 빠짐없이 수집해 시계열로 쌓고, 캐시로 안정적으로 서빙한다.** 이 세 기능 모두 이 가드 아래에서만 진행한다:
- 수집/캐시/event-impact **로직**은 변경하지 않는다(C의 "추적 확대"는 워치리스트 **데이터**만 늘리는 것 — 같은 수집기·같은 레이트리밋·같은 스키마).
- 실 API 키·시크릿은 서버 env에서만. 프론트에서 Lostark API 직접 호출 금지.

## 기능 A — 대시보드 3열 카테고리 레이아웃 (프론트 전용)

**현재:** `DashboardPage.tsx`가 2열(`lg:grid-cols-[minmax(0,1fr)_20rem]`, `max-w-6xl`) — 좌: 각인/재료 세로 섹션 + `AsyncBoundary`, 우: `NewsPanel`(~320px). `ItemCard`가 최저가·수집시각 표시.

**목표 레이아웃:**
- `lg` 이상 **3열** grid `[좌 카테고리 nav ~11rem | 중앙 물품 minmax(0,1fr) | 우 NewsPanel 20rem]`, 폭 `max-w-6xl → 7xl`.
- **카테고리**: 딜러 각인(DEALER) / 서포터 각인(SUPPORT) / 재료(MATERIAL), `sortByRole` 순서. **비어있는 카테고리 탭은 숨김.** 기본 선택 = 첫 비어있지 않은 카테고리.
- **상호작용(필터)**: 좌측에서 하나 선택 → 중앙엔 그 카테고리 물품만(기존 `ItemCard` 세로 스택 그대로 — 카드 **내용 무변경**). 상태 = 로컬 `useState`.
- **모바일(<lg)**: 좌 nav → 상단 가로 스크롤 칩 탭 → 물품 → 소식.
- **견고성**: 중앙 물품은 기존 `useItems()` + `AsyncBoundary` 재사용, 우 소식은 독립 boundary(현행 유지). `roleGroup=null` 품목은 현행처럼 미표시(큐레이션상 없음).

**컴포넌트 경계:**
- 신규 `CategoryNav.tsx` — 카테고리 목록·선택 표시·`onSelect`만 담당(데스크톱 좌 nav + 모바일 칩 동일 컴포넌트, 반응형).
- `DashboardPage.tsx` — 필터 상태 + 3열 grid + 카테고리 파생(데이터→카테고리 도출).
- `ItemCard`·`NewsPanel` **무변경**.

**Core Value:** 0줄(순수 프론트 read-path). **UI-SPEC 필요**(신규 레이아웃) → `/gsd-ui-phase`.

**미결정(C 이후 재검토):** 재련 재료 편입으로 "재료" 카테고리가 커지면 하위 분류(재련/상급재련/융화 등)를 나눌지 — 실제 품목 집합(C 스파이크)을 보고 확정.

**동기:** 차원술사(신규 직업, 2026-07-08 출시) 출시 기점으로 "타격의 대가" 각인서 가격이 급등 후 정상화 — "신규 캐릭터 출시" 카테고리가 있으면 이 상관을 정확히 기록·표현할 수 있다.

**변경(전부 additive, DB 마이그레이션 불필요):**

- `frontend/src/features/timeline/eventMarkers.ts`: `EVENT_MARKERS`(`Record<EventType,...>`이라 누락 시 컴파일 에러)에 색·라벨 3개. 마커 색은 기존 4색(violet `#7C3AED`/orange `#EA580C`/pink `#DB2777`/teal `#0D9488`)과 구분되는 접근성 3색(제안: 인디고 `#4F46E5` / 레드 `#DC2626` / 슬레이트 `#64748B`) — **dataviz 스킬로 대비 검증**.
- `frontend/src/features/admin/EventSection.tsx`: `EVENT_TYPE_LABELS`·`EVENT_TYPE_ORDER`에 3개.

**라벨:** 사용자 표현 그대로(신규 캐릭터 출시 / 신규 레이드 출시 / 일반 패치).
**테스트:** 백엔드 IT에 새 타입 왕복(create→read) 1케이스 + 프론트 스키마 파스. event-impact는 타입 무관(occurredAt 상관)이라 회귀 없음.
**Core Value:** 0줄. **UI-SPEC 불필요**(기존 폼·레전드에 옵션만 추가하는 델타).

## 기능 C — 시세 범위 확장 (스펙업 재료)

### 핵심: API 경계로 갈린다

| 대상 | API | 상태 |
|------|-----|------|
| 재련 재료 (파괴석·수호석·돌파석·파편·융화재료·숨결·야금술/재봉술 상급재련) | **거래소 MARKETS** (`GET /markets/options`, `POST /markets/items`) | ✅ 기존 API 그대로. 유한(수십 품목) |
| 보석 (T4, 8~10레벨, 클래스 무관) | **경매장 AUCTIONS** (`POST /auctions/items`) | ⚠️ 새 API. 이름검색("10레벨 겁화")으로 클래스 무관 조회 가능. 집합 작음 |
| 아크그리드 젬 | **스파이크로 확정** (경매장 유력 / 거래소 230000 가능) | ⚠️ Stage 0에서 확정 |

**근거(실측·문서):** 프로젝트 스파이크가 MARKETS 카테고리 트리(각인서 40000, 강화재료 50000→재련재료 50010/추가 50020/기타 51000/무기진화 51100/아크그리드재료 230000)를 실측. 웹 확인: 보석은 경매장 API에서만 검색(이름만으로 조회 가능), 상급 재련 재료 = 야금술·재봉술.

### 규모/비용 분석 (왜 이 범위가 안전한가)

- **레이트리밋(100/min):** 현재가 훑기는 카테고리 페이지 검색(~10/page)이라 저렴. 재련 재료 수십 개 추가 수집도 틱당 여유(수십 콜 ≪ 100/min).
- **DB 저장:** `price_snapshot` = (품목 × 10분 틱)/행. 1품목 ≈ 5.3만 행/년. **~20(현재)→~50 품목이어도 연 수백만 행 — 무료 VM(4GB Postgres) 여유.** (수백~수천 품목·경매장은 롤업/파티셔닝 필요 → 범위 밖.)
- 결론: "현재가 둘러보기"는 싸고, "조밀 시계열 영구기록"은 두 축(호출·저장) 모두에서 비싸다 → **유한한 재련 재료는 추적(기록)까지 안전**, 보석/경매장은 별도 단계로 신중히.

### C 세부 (단계)

- **Stage 0 (스파이크):** 거래소 재련재료 카테고리·품목 실측·잠금(Phase 12 spike-then-lock 패턴). 산출: `external_item_id`/`display_name`/`category_code`/`icon_url`/`item_group`/`role_group` 표. 아크그리드젬 API 위치 확인. 재료 하위분류 후보 도출.
- **Stage 1 (재련 재료 추적):** 잠근 재료를 `WatchlistSeeder`/seed/enrichment에 추가 → 수집기가 10분 시계열 축적. **수집 로직 0줄**(데이터만). 레이트리밋 여유 검증. 재료 하위분류(필요 시) 반영.
- **Stage 2 (경매장 — 보석·아크그리드젬):** 새 AUCTIONS 클라이언트·파서, **현재가 둘러보기**(시계열 영구기록 아님 → DB 폭증 없음). 별도 마일스톤 후보(v1.6).

**스코프 경계 진화(명기):** PROJECT.md는 "경매장(AUCTIONS)·보석 = v2, 데이터 소스 거래소만"으로 명시. **Stage 2는 이 경계를 의도적으로 넓히는 것** — 단, 보석은 "현재가 둘러보기"(온디맨드·캐시)로 한정해 Core Value(거래소 시계열 수집)를 오염하지 않는다. 마일스톤 문서에 이 진화를 반영한다.

## 스파이크로 잠글 미결정 항목 (추측 금지)

- 정확한 재련 재료 품목 집합 + leaf 카테고리 코드 (숨결·야금술·재봉술의 정확한 카테고리 포함).
- 재료 하위분류: 단일 "재료" vs 재련/상급재련/융화 세분 (대시보드 카테고리에 반영).
- 아크그리드 젬: 경매장(AUCTIONS) vs 거래소(230000).
- 경매장 보석의 "현재가" 표현: BuyPrice(즉시구매) 최저 vs BidStartPrice — Stage 2 스파이크.

## 리스크 / 주의

- **큐레이션 서사 유지:** 재련 재료 확대는 "덤프"가 아니라 "스펙업 재료 전반"이라는 의도적 큐레이션(면접 서사). 스파이크에서 유효 품목만 잠근다.
- **경매장 진입(C2)**은 스코프 경계를 넘으므로 별도 마일스톤에서 명시적으로 결정.
- 이벤트 마커 색 7종 대비 — dataviz로 접근성 검증(색만으로 구분 의존 금지, 기존 dash 패턴 유지).
```
