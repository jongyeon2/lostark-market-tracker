## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → frontend build | `npm install` pulls Vite/React/Tailwind/shadcn deps and their transitive tree onto the dev machine and into the bundle |
| Browser → Vite dev proxy → backend :8080 | The dev server forwards `/api/*` to the local Spring backend; the proxy is the only backend integration |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-0701-01 | Tampering (supply chain — npm deps) | package.json deps | mitigate | Use only first-party, widely-used packages (Vite, React, Tailwind, shadcn/ui official registry, lucide-react) at current major versions from the public npm registry; NO third-party shadcn registry (UI-SPEC Registry Safety PASS), no `curl \| sh`, no postinstall scripts from unknown packages. Lockfile (`package-lock.json`) pins the resolved tree for reproducible installs. |
| T-0701-02 | Information Disclosure (secret leakage into the bundle) | .env / Vite env | mitigate | The frontend stores NO secret: only `VITE_API_TARGET` (a localhost URL) is exposed, and Vite only inlines `VITE_`-prefixed vars by design. `.gitignore` excludes `.env`; `.env.example` documents only the non-secret proxy target. No `LOSTARK_API_KEY` / `ADMIN_API_SECRET` is ever referenced in `frontend/`. |
| T-0701-03 | Spoofing / SSRF (proxy retargeting) | vite.config proxy | accept | `VITE_API_TARGET` lets a developer repoint the dev proxy; this is a local-only dev convenience (the dev server is not a production surface) and defaults to `http://localhost:8080`. Acceptable for a dev-only proxy; production static serving is out of scope (DEMO-03). |
| T-0701-04 | Tampering (accidental backend change) | repo src/ | mitigate | The plan creates files ONLY under `frontend/`; an explicit acceptance check (`git status --short -- src/` is empty) enforces the "backend unchanged" user constraint, so no Spring CORS/static change sneaks in. |
</threat_model>
