<objective>
Deliver the **event-impact v1 metric endpoint** (`GET /api/items/{id}/event-impact?window=N`, IMPACT-01): for the queried item, compute **per game_event** the **anchor single-snapshot delta** `change_rate = post / pre − 1` where `pre` is the last `min_price` snapshot at-or-before the event within ±N hours and `post` is the first at-or-after it (design §79, **not** a window average — D-01). Events are evaluated **globally** (the event log is not per-item, D-06) and returned **occurred_at desc** as a per-event list with a `status` field (D-07). The `window` parameter is a **required integer hours** value with the Phase 3 validation contract (≤0 / >cap / missing / non-integer → **400**, missing item → **404**, D-08), all reusing the existing `ApiExceptionHandler` — no new exception types.

The headline engineering signal of this wave is **N+1 avoidance (D-09, design T7)**: calling the 4A `WindowQueryService.fetchWindow` per event would be `2N` queries, so instead the service fetches **all events once** and the item's snapshots for the **whole `[min(occurred_at)−Nh, max(occurred_at)+Nh]` span in a single call** to the existing `PriceSnapshotRepository` range finder, then derives every event's anchors **in memory**. An IT spy proves the snapshot finder runs **exactly once** regardless of event count.

This wave builds the *capability and the happy path*: events that have both a pre and a post snapshot in their window return `status:"ok"` with `change_rate`; events missing a side are still listed with `status:"insufficient_data"` (the presence floor). Plan **05-02 (Wave 2)** layers the **staleness allowance (D-03/D-04)** and finalizes the **precise insufficient_data anchor-time contract (D-02/D-05)** on top of this service. To make that drop-in with **zero test retrofit**, this wave's happy-path IT places its anchor snapshots **within 30 minutes** of the event, so they stay `"ok"` once the staleness gate lands. **Correlation ≠ causation** (PROJECT premise 5): `change_rate` is a *temporal correlation* number — the response and any wording must not assert the event *caused* the move.

Output: `EventImpactResponse` + `EventImpactItem` DTOs; `EventImpactService` (read package, batch anchor-delta); `EventImpactController` (`/api/items/{id}/event-impact`); a `findAllByOrderByOccurredAtDesc` finder on `GameEventRepository`; and `EventImpactIT` (Testcontainers).
</objective>
